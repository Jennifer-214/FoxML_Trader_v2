# v4.7.21 — W/L pairing under partials + chart Y-fit fix

**Date:** 2026-04-28
**Branch:** experiment/per-core-sharding

Two unrelated fixes shipped together — both came out of the same live-observation pass.

---

## (1) W/L classification pairs leg A + leg B by net P&L

### Symptom

With `partial_exit_enabled=1`, every paired trade has TWO exit fills (leg A at TP1, leg B at TP2 or SL). Pre-v4.7.21 the leg-A exit alone bumped `core_wins` or `core_losses` based on leg A's outcome:

- TP1 + TP2 → leg A wins → `1W` ✅
- TP1 + SL → leg A wins → `1W` ❌ (actual net: leg A's small gain minus leg B's larger loss = net negative; counted as a win because leg A took TP1)
- SL + SL → leg A loses → `1L` ✅

The TP1+SL case is the trap: the trade idea LOST money but the W/L counter showed a win. Sessions running partials would show inflated win-rates compared to actual P&L.

### Fix

Per-trade W/L classification by **net P&L** when partials are enabled. First leg to close stashes its `exit_net_pnl` in a new `partner_pending_pnl` field on `CoreContext`. When the partner closes, sum the two and classify by sign:

```
total_net = pending + current
if total_net > 0  →  core_wins++
else              →  core_losses++
```

One bump per trade idea, regardless of which leg closed first.

When `partial_exit_enabled=0`, the pairing block is bypassed and the existing per-leg-A logic stands (single-leg trades have no partner; the leg-A path is the only fill site).

### What still fires per-leg

`core_realized`, `core_open_notional`, `core_fees`, `state.total_exits`, `state.cores[].exits_processed` — all still per-leg. Each fill contributes its own qty + fees + notional. Only the `core_wins`/`core_losses` semantic changed.

`ConfidenceScorer_Update`, `RegressionFeederX_Push`, `sl_cooldown_remaining`, and `active_prediction` reset stay leg-A-only — they're tied to the original prediction and TP1 outcome, not the trade's net P&L.

### CSV granularity unchanged

The trade log CSV still records per-leg rows (one per fill). Forensic detail is preserved: a tuner can still see TP1 hit at +X bps then SL hit at -Y bps as two separate rows. Only the in-engine W/L counter (Stats panel headline + Per-Core P&L panel) became per-trade.

### Tests

Three regression cases in `controller_test.cpp`, 8 new assertions:

1. **TP1 + TP2** (both win): `core_wins == 1`, `core_losses == 0`, pairing flag cleared
2. **TP1 + SL** (split, net negative): `core_wins == 0`, `core_losses == 1`
3. **Partials disabled**: per-leg-A path still produces `1W` per single-leg win, pending stash never set

685/685 tests pass.

## (2) Reset View no longer squashes price action

### Symptom

After clicking "Reset View" in the price chart, candles compressed into a thin band at the bottom of the chart while most of the Y space showed empty regime background. User had to manually toggle Y-autofit to recover.

### Root cause

The Y autofit loop walked **all** candles in the snapshot buffer (`vc = csnap->count`, up to 4096 candles ≈ session-wide). When the session contained a deep dip earlier (e.g. price spent time at $75800 hours ago, then recovered to $76200), the candle range became large enough that the expansion budget (`candle_range × 2`) included a position's SL line at $75516 — pulling the Y range out to span the SL even though no recently-visible candle goes anywhere near it.

Recent candles cluster at $76200 → $76250 (range ~$50), but SL at $75516 sits 700 pts below. With `candle_range = $400` from session-wide walk, expand_lo = $76020 - $400 = $75620 (NOT including SL). But when session-wide range is larger (e.g. $600), expand_lo dips to $75200 — and SL at $75516 is now in the budget, gets included, dominates the Y range.

### Fix

Restrict the Y autofit candle loop to candles **within the post-reset visible X window** `[cs->x_lo, cs->x_hi]`:

```cpp
for (int i = 0; i < vc; i++) {
    if (cs->xs[i] < cs->x_lo || cs->xs[i] > cs->x_hi) continue;
    if (cs->lows[i] < y_min) y_min = cs->lows[i];
    if (cs->highs[i] > y_max) y_max = cs->highs[i];
}
```

Defensive fallback: if zero candles fall in the visible window (cold start / pan beyond data), revert to the all-candles loop so we don't end up with `y_min > y_max`.

### Bonus: `Show All Levels` opt-in toggle

User wanted the option to see ALL TP/SL lines simultaneously (full risk geometry) without making it the default. Added `bool show_all_levels = false` to `ChartSettings` + a checkbox in the chart toolbar. When ON, the per-position TP/SL expansion loop includes every level unconditionally (no expansion-budget gate). Default OFF — clicking Reset View fits to candles + nearby TP/SL only.

### Surface area

- `GUI/ChartPanel.hpp`: ~10 LOC of substantive change (new field, checkbox UI, candle loop X filter, conditional in expansion loop). Surrounding comments updated.

Pure GUI thread, hot path untouched.
