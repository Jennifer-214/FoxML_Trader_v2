## Phase 5: per-core ML model zoo + 3-class softmax barrier

**Commit:** `42a4b1b feat: Phase 5 — CoreModelZoo + 3-class softmax BarrierGate`

Architectural pivot from "single ML model per core" to "per-core model zoo with role-specific models." Each ML core now points at a directory and the engine auto-discovers role-specific models in it.

```
models/aggressive/
  barrier.json       # 3-class P(stable)/P(peak)/P(valley) — primary
  buy_signal.json    # legacy single-binary (backward compat)
  regime.json        # multi-class regime classifier (future)
  exit.json          # exit timing (future)
```

- New `ML_Headers/CoreModelZoo.hpp` — zoo struct + dir loader
- `Model_PredictMulti` in `ModelInference.hpp` — multi:softprob support
- `core_N_model_dir` config field (`char core_model_dir[16][256]`) with parser
- `LABEL_PEAK_VALLEY_STABLE` (id 7) in `LabelFunctions.hpp` + `Label_PeakValleyStable` 3-class first-passage scan
- `ML_BuildParameters` rewritten to consume zoo + apply BarrierGate continuous modulation:
  - 3-class barrier model loaded → real `p_peak` / `p_valley`
  - only `buy_signal` loaded → complementary interpretation (1 - prediction)
  - `barrier_gate_enabled` → continuous gate ∈ [g_min, 1.0] scales `trade_size`
  - `barrier_gate_disabled` → legacy binary threshold path preserved
- Training panel: 8-label dropdown (was 4), `multi:softprob` objective when label is REGIME or PEAK_VALLEY_STABLE, multiclass argmax accuracy

Hot path untouched. All changes are slow path. Per-tick cost still 13 ns. 279/279 controller_test still passing.

**Decision rationale (3-class softmax over dual-binary):**
- Mutual exclusivity enforced by softmax (can't have `p_peak=0.7 AND p_valley=0.7`)
- Calibrated probabilities (vs uncalibrated dual-binary)
- "Stable" class is informative — explicit no-decision signal
- Single training run, single model file
- Asymmetric class priors handled by softmax automatically

**Decision rationale (zoo over flat per-core paths):**
- Forward-compatible (regime model, exit model added without ripple)
- One config field per core (model_dir) vs four (one per role)
- Missing roles silently no-op → graceful degradation
- Bundle directory = atomic deployment unit + SHA256 fingerprint scope

## Stupid-proof model deployment

**Commit:** `c317d44 feat: stupid-proof model deployment — bundle expected.cfg + verify on load`

When a model is saved via the Training panel, the run bundle now includes an `expected.cfg` capturing the ML-relevant config fields used during training. On load, the engine compares live config against `expected.cfg` and either warns, fails, or skips per `model_verify_strict`:

- `model_verify_strict = 0` → warn (default, dev-friendly)
- `model_verify_strict = 1` → fail load on mismatch (production)
- `model_verify_strict = -1` → skip verification entirely

`CoreModelZoo_VerifyExpected` extends to `slow_path_interval` and `min_warmup_samples` (Phase 5d Wave 2 plan). `expected.cfg` writer in `BacktestPanels.hpp` Save Run handler.

## Backtest infrastructure

### Equity curve dynamic allocation

**Commit:** `ff9ac48 fix: equity_curve dynamic allocation — silent truncation contaminated stats`

Replaced `double equity_curve[BACKTEST_MAX_EQUITY]` (cap 8192) with dynamically grown buffer. Long backtests at 50–200 trades/day across multi-year datasets exceed any small fixed cap. Stats (Sharpe / max DD / return) compute from this array — silent truncation = wrong stats. New `BacktestResults_EnsureEquityCapacity` grows 2× when full.

### Equity curve preservation bug + `_Reset` helper (uncommitted, fixed today)

The above fix introduced a latent bug. `Backtest_Run` and `BacktestSharded_Run` had hand-rolled save/restore blocks around `memset(results, 0, sizeof(*results))` to preserve dynamic pointers between runs. The `equity_curve` and `equity_capacity` fields were not added to that save/restore. So on the second run (and every run after):

- `equity_capacity = 0` after the reset
- First trade exit calls `BacktestResults_EnsureEquityCapacity(needed=1)`
- `new_cap = 0 * 2 = 0`
- `while (0 < 1) new_cap *= 2;` — **infinite spin at 100% CPU on the worker thread**, no stderr output

Symptom: file 1 of N loaded, warmup completed, a few trades happen, then the worker goes silent. Chart frozen mid-day-1, GUI sees "still running" forever, no log lines because the spin is in a pure-arithmetic loop with no I/O.

**Fixes shipped:**

1. **`BacktestResults_Reset()` helper** — single source of truth for "reset counts but keep heap allocations." Both run paths now call it instead of duplicating save/restore.
2. **Floor in both `Ensure*Capacity` helpers** — `cap > 0 ? cap*2 : INIT_CAP`. Defense-in-depth against the next time someone adds a dynamic field and forgets `_Reset`. Same idiom in both helpers, cross-references each other in comments.
3. **CLAUDE.md** — added a "Dynamic-buffer lifecycle invariant" subsection under Dynamic Sizing. Names the four sites that need to update together (Init/Reset/Free/EnsureCapacity), with the postmortem inline.

**Audit results (other sites at risk):**
- `Backtest/BacktestSharded.hpp:101` had the same bug → fixed by using `_Reset`
- `BacktestResults_EnsureCapacity` (samples) had the same `cap *= 2` floor-zero potential → bulletproofed (sample_capacity was being preserved, so unreachable, but defense-in-depth)
- `Backtest/BacktestPanels.hpp:878` `memset(&state->wf_results)` — safe: `WalkForwardResults` is all POD
- All other `memset` sites (10+ in our code) reset structs with no heap members — clean

## Postmortem: why the spinner happened

Three factors compounded:

1. **Hand-rolled save/restore.** Two run paths each duplicated knowledge of "which fields are heap allocations." When `equity_curve` was added as the 6th dynamic field, both copies had to be updated. Only `_Init` and `_Free` were updated. The reset blocks were missed.
2. **Defensive helper without a defensive floor.** `EnsureEquityCapacity` assumed `equity_capacity > 0`. `cap *= 2` is an infinite loop when `cap == 0`.
3. **No instrumentation in the spin.** The loop body is pure integer arithmetic — no `fprintf`, no syscall. So 100% CPU + dead-silent log was the only signal. Without the new log viewer (`15f2ac0`) routing stderr to a file we could read after the fact, this would have been much harder to diagnose.

**What changed structurally to prevent recurrence:**

- `BacktestResults_Reset()` is now the single source of truth. Future dynamic field additions update one function instead of two manual reset blocks.
- `Ensure*Capacity` helpers floor at the init constant. Even if `_Reset` is somehow missed in the future, the spinner class is dead.
- CLAUDE.md "Dynamic-buffer lifecycle invariant" subsection makes the four-site update rule explicit.
