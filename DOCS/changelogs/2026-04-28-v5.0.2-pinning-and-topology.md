# v5.0.2 — slow-path pinning + Engine Topology panel (2026-04-28)

Two follow-on items from the v5.0.0 architectural switchover. Both are
quality-of-life polish on the new per_core_slow architecture, not
behavior changes.

## (1) Slow-path CPU pinning

Added `cfg.slow_path_pin_offset` (int, STARTUP-ONLY):

| Value | Behavior |
|------:|----------|
| `< 0` | Do not pin slow-paths (OS-scheduled — original v5.0 behavior). |
| `== 0` | **Default.** Auto-derive: base = `num_execution_cores + 2` (one CPU past the drainer at `num_cores + 1`). |
| `> 0` | Explicit base CPU. |

Slow-path `c` pins to `(base + c) mod nproc`. HT-sharing is acceptable
since slow-paths are jitter-tolerant (cadence is poll-driven, microseconds
of work per cycle). Best-effort: pin failure is logged via the existing
`EngineSharded_PinThread` helper and execution continues unpinned.

Existing pin layout (unchanged): producer = CPU 0, hot-paths = CPU 1..N,
drainer = CPU N+1. Slow-paths now go past that into N+2 onwards.

Centralized arch (`engine_arch=centralized`) is unaffected — there are
no slow-path threads to pin.

Set `slow_path_pin_offset=-1` to disable pinning for benchmark
comparison or on systems where CPU-spread isn't beneficial.

## (2) Engine Topology panel (GUI)

New ImGui panel showing the static thread layout. Three sections:

1. **System** — `engine_arch` (per_core_slow / centralized), system
   `nproc`, and `slow_path_pin_offset` interpretation (auto / explicit /
   disabled).
2. **Shared threads** — Producer CPU + Drainer CPU.
3. **Per-engine threads** — table with one row per engine: Strategy
   (resolved if AUTO), Hot CPU, Slow CPU, Poll cadence (resolved
   per-core override or global). Slow CPU shows `(prod)` in centralized
   mode (slow-path runs on producer thread); shows `unpin` if pinning
   was explicitly disabled.

Reads new `TUISnapshot` topology fields populated by `TUI_PopulateTopology`
inside the GUI snapshot publish each cycle. Values are static after
spawn, so the publish cost is trivial (a handful of int copies).

Helps diagnose pin conflicts and contextualize per-engine slow-path
latency stats: "engine 3 is on CPU 7 which shares an HT with the
producer on CPU 0... wait, no, those aren't HT siblings on this box —
let me check `lscpu`."
