# v4.7.17 — Shared Slow-Path Helpers (Time-Exit + D9 Trailing SL)

**Date:** 2026-04-27
**Branch:** `experiment/per-core-sharding`
**Status:** experiment branch
**Prerequisite:** v4.7.16

## Summary

Architectural refactor closing two more train-serve drift sources by
extracting inline slow-path blocks from `EngineSharded_Run` into shared
helpers in `ControllerEventLoop.hpp`. Live + backtest now run the
**exact same function** for time-exit and D9 trailing SL.

## What was wrong

In v4.0.3 (2026-04-25), commits `0885e10` (A3 time-exit) and `f628eb8`
(D9 trailing SL ratchet) shipped both blocks of logic directly inlined
into `EngineSharded.hpp`'s slow path instead of extracting to the shared
header. ~80 LOC of trading logic that should have been shared became
live-only.

Symptoms (drift activates when user enables either feature in cfg):

- `cfg.max_hold_ticks > 0` (default 0) → live force-closes stale
  positions held longer than N ticks with gain below
  `cfg.min_hold_gain_pct`. Backtest holds them indefinitely. ML model
  trained on backtest never learns the early-exit pattern.
- `cfg.tp_hold_score > 0` (default 0) → live ratchets trailing SL
  upward when gain crosses threshold. Backtest never moves SL.
  Different exit prices for the same trades.

Both default to inert, so the drift hadn't surfaced in live trading
yet — but it would the moment user tunes either knob.

## Fix

Two new shared helpers in `CoreFrameworks/ControllerEventLoop.hpp`:

```cpp
template <unsigned F>
inline void EventLoop_TimeExit(EventLoopState<F>* state,
                                OrderManagerState<F>* oms,
                                const ControllerConfig<F>& cfg,
                                uint64_t now_tick,
                                double current_price);

template <unsigned F, unsigned W>
inline void EventLoop_TrailingSLRatchet(EventLoopState<F>* state,
                                         const ControllerConfig<F>& cfg,
                                         const RollingStats<F, W>& rolling,
                                         double current_price);
```

Same logic verbatim, parameterized over `now_tick` and `current_price`
so live (atomic loads) and backtest (tick_index + tick.price) supply
the same shape of input.

`EngineSharded.hpp`:
```cpp
uint64_t now_tick      = ticks_produced.load(std::memory_order_relaxed);
double   current_price = last_price.load(std::memory_order_relaxed);
EventLoop_TimeExit(&state, state.oms, cfg, now_tick, current_price);
EventLoop_TrailingSLRatchet(&state, cfg, rolling_short, current_price);
```

`ShardedBacktestDriver.hpp` (in `ShardedBacktest_RunTick`'s slow-path block):
```cpp
double current_price = FPN_ToDouble(tick.price);
EventLoop_TimeExit(drv->state, drv->oms, *drv->config,
                   (uint64_t)tick_index, current_price);
EventLoop_TrailingSLRatchet(drv->state, *drv->config,
                             *drv->rolling, current_price);
```

Inline blocks in `EngineSharded.hpp` (~80 LOC) deleted.

## Live behavior preservation

Live's slow-path semantics are unchanged. Differences vs pre-v4.7.17
inline code:

1. **One fewer atomic load.** Pre-v4.7.17 the trailing-SL block called
   `last_price.load()` on its own. Refactor reuses the snapshot loaded
   for time-exit. Slightly more consistent (both decisions see the same
   price for a given slow-path cycle), zero perf impact.
2. **Log message prefix changed**: `[sharded] core %d: time-exit
   (held %lu ticks, gain %.3f%%)` → `[time-exit] core %d: held %lu
   ticks, gain %.3f%%`. Cosmetic. The shared function describes the
   feature, not the source.
3. **Hot path: untouched.** Helpers are slow-path only.

All gates, FPN ops, bitmap walks, snapshot-drift guards, force-close
logic, heartbeat counter bumps, ratchet-up checks (`FPN_GreaterThan`),
and `dirty=1` writes are bit-for-bit identical.

## Doctrine

This release re-establishes the architectural intent: **shared logic,
separate drivers**. `EngineSharded_Run` and `ShardedBacktestDriver`
should ONLY differ in:

| Concern              | Live                          | Backtest                |
|----------------------|-------------------------------|-------------------------|
| Tick source          | Binance WS (async)            | CSV file (sync replay)  |
| Threading            | Producer + drainer + GUI      | Single thread           |
| Order placement      | Real Binance API              | Simulated fills (instant, all-taker) |
| Time                 | Wall clock                    | CSV timestamps          |
| Persistence          | Snapshot save/load            | Per-run reset           |

Trading logic — strategies, gates, regime detection, per-core
bookkeeping, slow-path policy blocks, ConfidenceScorer feedback,
DrainPostFill, time-exit, trailing SL — lives in shared headers
(`ControllerEventLoop.hpp`, `Strategies/`, `ML_Headers/`) and is
called by both drivers.

Adding the next slow-path gate goes into the shared header by default.
