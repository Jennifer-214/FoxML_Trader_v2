# 2026-04-25 (overnight) — v4.0.3: sharded strategy feature parity

Twelve commits porting legacy `PortfolioController` strategy features to
the sharded engine. Brings sharded from "minimum-viable strategy stubs"
to ~80% feature parity with legacy, while preserving the branchless +
FPN + cache-aligned hot-path invariants.

## Audit that triggered this

While testing live, surfaced that **~60+ cfg fields were silently
ignored in sharded mode** — visible in the GUI Settings panel, parsed
correctly by the cfg loader, but the strategy code never read them.
Examples: `entry_offset_pct` (MR/MOM had no depth requirement),
`spacing_multiplier`, `vwap_offset`, `min_long_slope`, `min_buy_delta`,
`min_stddev_pct`, `tp_hold_score`, `sl_trail_mult`, `fee_floor_mult`,
`max_hold_ticks`, `sl_cooldown_cycles`, all session multipliers, all
spike fields, all adaptive feedback fields.

Each one was tunable in the GUI but had zero effect at runtime. This
release wires the operationally-important ones.

## What got ported

### A1: spacing_multiplier (commit d5de16e)
Cross-cutting check in `EventLoop_RebuildAllParameters` post-process.
Zero-gates entry if `|proposed_entry - last_entry_price| < stddev ×
spacing_multiplier`. Prevents clustering positions at similar prices
(correlated wins/losses, not real diversification). CoreContext gains
`last_entry_price`, set in drainer on entry submit.

### A2: fee_floor_mult (commit d5de16e, paired with A1)
After computing TP, ratchet up if `tp_amount < entry × fee_rate ×
fee_floor_mult`. Round-trip fees = 2×fee_rate, so fee_floor_mult=5
means TP must clear ~2.5× round-trip fees + margin. Prevents trades
that can't profit after fees. Helper: `Strategy_TpFloor`.

### A3: time-based exit (commit 0885e10)
Slow path walks active positions; if `held > max_hold_ticks AND
gross_pnl_pct < min_hold_gain_pct`, drainer submits SELL. Frees stuck
positions in dead markets without closing winners.

### B: STRATEGY_AUTO regime mode (commit 6e124b5)
Each core can run as `core_N_strategy=auto` (or `regime`). Slow path
classifies regime via `Regime_Classify` with per-core hysteresis
state, looks up `REGIME_STRATEGY_TABLE[regime]`, dispatches to that
strategy. Mirrors legacy `default_strategy=-2` but per-core — different
cores can detect different regimes.

`STRATEGY_AUTO=5`, `NUM_STRATEGIES=6`. Added to GUI dropdown
(`AUTO`), cfg parser (`auto`/`regime`), short/full names. Each AUTO
core has its own `RegimeState`.

### D1-D4: filter gate cluster (commit caa8128)
- **VWAP gate (`vwap_offset`)**: zero-gate if entry > VWAP - VWAP×offset
- **Long-slope gate (`min_long_slope`)**: zero-gate if 512-tick relative
  slope below threshold (confirmed downtrend)
- **Volume delta gate (`min_buy_delta`)**: zero-gate if net selling pressure
- **Min stddev gate (`min_stddev_pct`)**: zero-gate when stddev/price below
  threshold (dead market)

All four "zero-gate if violated" filters in the post-process block.

### D5: volume spike spacing relaxation (commit d6228ab)
When current vol >= max / spike_threshold, multiply spacing requirement
by spike_spacing_reduction. Real volume bursts are valid second-entry
opportunities — don't artificially space them out.

### D6: session-aware volume multiplier (commit d6228ab)
UTC-hour-based session detection (Asia 00-07, Europe 07-13, US 13-20,
Overnight 20-00). Multiply `volume_multiplier` by per-session value.
Lets cfg require less volume confirmation during quieter sessions.

### D7: SL cooldown (commit 957f5f1)
After any losing exit, pause new entries on that core for
`cfg.sl_cooldown_cycles` slow-path cycles. Prevents revenge trading
after a stop-loss. Set in `drain_confidence_feedback` (now also walks
non-ML closes).

### D8: halt reason tracking (commit 957f5f1)
Per-core `halt_reason` byte tracking why the entry gate is closed:
0=ok, 1=spacing, 2=vwap, 3=long-slope, 4=vol-delta, 5=min-stddev,
6=sl-cooldown. First-reason-wins (filters checked in order).
Surfaces in GUI per-core panel for easy diagnosis.

### D9: trailing SL ratchet (commit f628eb8) — preserves branchless+FPN

Real hot-path trailing without breaking architecture invariants. Added
`ratchet_sl` field to GateParameters. Hot path SG_Evaluate uses
`effective_sl = FPN_Max(active_sl, ratchet_sl)` — branchless, FPN-pure.
When ratchet is FPN_Zero (default), `Max(sl, 0) = sl` so behavior is
unchanged. When controller has ratcheted up, ratchet wins.

Cost: ~5ns added per tick (one FPN_Max). Hot path stays branchless +
FPN. Propagation via existing ParameterSlot seqlock — no new atomic
protocol needed.

Slow path checks each active position; if `gain >= cfg.tp_hold_score`,
computes trailing target = `current_price - (stddev × sl_trail_mult)`.
Only ratchets UPWARD (FPN_Max enforces this in hot path; controller
also checks before writing). `ratchet_sl` cleared each rebuild when
no position is active.

Tradeoff vs hot-path-fast trailing (atomic-double mirror): bounded by
slow-path cadence (~100-200ms) for the SET, microseconds for the FIRE.
For crypto where moves take seconds, this is fine. The atomic-double
approach was prototyped and reverted because it broke branchless+FPN.

### D10: adaptive feedback loop (commit ffb154b)
Per-core P&L regression drives `entry_offset_pct` + `volume_multiplier`
shifts on each slow-path rebuild. Negative slope (recent losses) →
tighter filters. Positive slope (recent wins) → looser filters. R²
gated at 0.20. Clamped to `cfg.offset_min/max` + `vol_mult_min/max`.

CoreContext gains `RegressionFeederX pnl_feeder` (8-sample window).
Drainer pushes realized return on each exit.

### D11: per-core regime adjustment of running positions (commit 378e9b0)
When AUTO core's regime CHANGES mid-position, tighten `ratchet_sl` to
`rolling.price_avg - stddev`. Locks in any open profit ahead of the
strategy switch. Uses the D9 ratchet mechanism (no atomic protocol
needed).

## What stayed deferred to future sessions

Documented in `plans/post-v4.0-followups.md`:

- **Partial exits** (~4-5 hr surgery — two-positions-per-core, requires
  Portfolio slot allocation rework)
- **Per-fill slippage compensation in trailing** — `live_tp/live_sl`
  set at actual fill price already exists; trailing uses ratchet on
  top, doesn't read live_*. Could be unified.
- **Strategy-specific full ports of MR/MOM stub logic** — current
  stubs use `entry_offset_pct` correctly (v4.0.3) but lack the
  RegressionFeederX-based adaptive offset shifts of legacy. Cross-
  cutting D10 helps but isn't strategy-specific.
- **EmaCross full port** — still delegates to SimpleDip with TP/SL
  override. The actual EMA crossover detection isn't implemented.
- **GUI per-core halt_reason display** — `halt_reason` is tracked but
  not yet shown in the Buy Gate panel's per-core table.

## Hot-path audit (architecture invariant check)

What I added to `ExecutionCore_Tick` tonight:
- GATE_FLAG_BUY_ABOVE branchless mask select (~1ns, FPN-pure)
- FPN_Max(sl, ratchet_sl) for trailing (~5ns, FPN-pure, branchless)
- (D9 atomic-double mirror prototyped, REVERTED — broke invariants)

Net hot-path overhead from v4.0.3: ~6ns. Combined with v4.0.0-v4.0.2
adds, hot path is still well under 500ns p99 budget. Architecture
preserved: branchless + FPN<F> + cache-aligned.

Everything else (12 of 12 ported features) is slow-path — runs at
~5Hz on the producer thread, doesn't touch ExecutionCore_Tick. No
hot-path cost.
