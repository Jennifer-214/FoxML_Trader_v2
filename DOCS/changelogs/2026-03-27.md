# Changelog: March 27, 2026 (Profitability + Latency Overhaul)

## [3.1.0] - 2026-03-27

### Context
31 hours of paper trading produced -$128 (-1.28%) with 28.7% win rate. Root causes: fee-floored TP unreachable when stddev small, no macro trend filter, 10-position pyramiding into same losing trade, no volume delta signal, hidden downtrends misclassified as RANGING.

### Added
- **Volume delta signal** — Parse Binance `"m"` (is_buyer_maker) field from trade JSON. Track directional buy/sell volume in RollingStats. Compute `volume_delta = (buy-sell)/(buy+sell)` per window. New field in RegimeSignals for regime detection. MR buy gate blocks entries when heavy selling pressure (`min_buy_delta` config, default -0.3).
- **Hidden downtrend detection** — Regime classifier now catches macro downtrends disguised as RANGING. When 512-tick slope is strongly negative (2x threshold) but 128-tick slope is flat, counts as a down signal. Triggers TRENDING_DOWN through existing scoring, pausing buys. Previously 65 of 77 MR stop-losses fired while engine thought it was RANGING.
- **Minimum volatility filter** — Skip fills when `stddev/price < min_stddev_pct` (default 0.0003 = 0.03%). Prevents entries where fee-floored TP is geometrically unreachable by stddev-based SL.
- **Momentum R² floor** — Block momentum entries when `price_r_squared < momentum_r2_min` (default 0.4). Prevents breakout buys in choppy markets where R²-adaptive SL creates inverted R:R.
- **DOCS/KNOWN_ISSUES.md** — Documents FPN saturation risk on running totals (weeks-scale) and config hot-reload race condition (low practical risk).

### Changed (Latency)
- **Compiler flags** — `-O2` → `-O3 -march=native -funroll-loops -flto`. FPN word loops benefit from auto-vectorization and LTO inlines across the full hot path.
- **BuyGate inline comparison** — Replace `FPN_LessThanOrEqual`/`FPN_GreaterThanOrEqual` (18 word reads + 8 comparisons each) with inline positive-FPN word comparison matching PositionExitGate pattern. BuyGate 102ns → 53ns.
- **ExitGate branchless** — Replace `||`/`&&` (short-circuit branches) with `|`/`&` (bitwise). Assembly-verified: eliminates `jb` branch, produces pure `cmp`/`set`/`and`/`or` sequence.
- **Position struct reorder** — Move `take_profit_price` and `stop_loss_price` to front of Position struct. ExitGate reads both from cache line 0 instead of straddling 64-byte boundary.
- **Portfolio struct reorder** — Move `active_bitmap` to offset 0 (was at 2304 after 16 positions).
- **ExitBuffer struct reorder** — Move `count` to offset 0 (was at 768 after 16 records).
- **DataStream struct reorder** — Move `is_buyer_maker` before doubles, keeps all hot fields in cache line 0.
- **RollingStats struct reorder** — Move `side_buf` after ring buffers, before head/cached outputs. Eliminates 4 cache line gap between head and side_buf during push.
- **Snapshot version** — 4 → 5 (Position + Portfolio layout changed).

### Changed (Strategy)
- `max_positions`: 10 → 3 (stop pyramiding into same losing trade)
- `fee_floor_mult`: 5.0 → 3.0 (TP floor 0.5% → 0.3% of price — reachable)
- `offset_stddev_mult`: 1.5 → 2.5 (demand deeper dips, filter noise)
- `take_profit_pct`: 4.0 → 3.0 (TP = 3σ, closer target, higher hit rate)
- `stop_loss_pct`: 6.0 → 4.0 (SL = 4σ, wider than TP, >1:1 R:R)
- `min_long_slope`: 0 → -0.0001 (enable existing 512-tick trend gate)
- `momentum_sl_mult`: 2.0 → 1.5 (tighter SL, cut losses faster)
- `tp_hold_score`: 0.2 → 0.1 (activate trailing earlier)

### New Config Fields
- `min_buy_delta` — Min volume delta for MR buys (default -0.3, 0 = disabled)
- `min_stddev_pct` — Min stddev/price ratio for fills (default 0 in code, 0.0003 in engine.cfg)
- `momentum_r2_min` — Min R² for momentum entries (default 0 in code, 0.4 in engine.cfg)

### Late-Night Additions
- **time(NULL) syscall gate** — Skip syscall on 84/100 ticks via bitmask (`tick_count & 0xF`). Only check time floor every 16th tick. Saves ~500ns per tick on the fast path.
- **DrainExits guard** — Gate on `exit_buf.count > 0` to match warmup pattern.
- **DOCS/FAILED_OPTIMIZATIONS.md** — Two struct reorder attempts that made latency worse. Root cause: false sharing (v1) and prefetch pattern breakage (v2). The "accidental" layout where writes pre-warm buy_conds' cache line is actually optimal.
