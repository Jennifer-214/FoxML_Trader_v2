# v5.1.1 — Slow-path work breakdown profiling (2026-04-28)

Fifth and final v5.1 polish item. Closes the migration.

## What's new

### Per-section latency stats

`CoreContext::slow_path_breakdown[5]` — array of `CoreLatencyStats`, one
per slow-path section:

| Section | Constant | What it measures |
|--------:|----------|------------------|
| 0 | `SP_SECTION_REBUILD` | `EventLoop_RebuildOneCore` call + per-cadence pushes |
| 1 | `SP_SECTION_PUSH_PARAMS` | seqlock push of pending_params to ExecutionCore |
| 2 | `SP_SECTION_TIME_EXIT` | `EventLoop_TimeExitOneCore` |
| 3 | `SP_SECTION_TRAIL_SL` | `EventLoop_TrailingSLRatchetOneCore` |
| 4 | `SP_SECTION_OTHER` | depth read + swap pickup + setup work |

Same single-writer rule as `slow_path_latency` — the thread that runs
the section is the sole writer. In `per_core_slow`, that's the per-core
slow-path thread. In centralized, sections aren't bracketed (the work
is sequential on producer; the breakdown is uninformative for one-thread
arch).

### Bracket pattern

Each section is wrapped with `__rdtsc()` deltas:

```cpp
uint64_t _sec_t_other_start = __rdtsc();  // outer marker
...
uint64_t _sec_t_rebuild_start = __rdtsc();
CoreLatencyStats_Sample(&breakdown[OTHER],
    _sec_t_rebuild_start - _sec_t_other_start, _sec_t_rebuild_start);
EventLoop_RebuildOneCore(...);
...
uint64_t _sec_t_push_start = __rdtsc();
CoreLatencyStats_Sample(&breakdown[REBUILD],
    _sec_t_push_start - _sec_t_rebuild_start, _sec_t_push_start);
```

5 brackets × ~5-10ns Sample = ~25-50ns per cycle. Slow-path is microsecond-
scale today (~10-50µs per cycle), so the overhead is < 1%.

### GUI breakdown table

New "Per-Engine Slow-Path Work Breakdown" sub-table inside the Per-Core
Latency panel:

| Engine | Strat | Other p50 | Other p99 | Rebuild p50 | Rebuild p99 | Push p50 | Push p99 | TimeExit | TrailSL | Σ p50 |
|---|---|---|---|---|---|---|---|---|---|---|

`Σ p50` sums all section p50s — should approximate the existing total
sp p50 (above the breakdown table) modulo measurement noise.

Use to debug per-strategy slow-path-heavy work: if one engine's Rebuild
p99 spikes while others stay flat, the strategy logic owns the cycle.

## Invariant C added (CLAUDE.md)

> **Per-Section Latency Stats Single-Writer**: Each
> `CoreContext::slow_path_breakdown[section]` is single-writer by the
> thread that runs that section (the slow-path thread that owns this
> core in per_core_slow; producer in centralized for cores it iterates).
> Reads via `CoreLatencyStats_Snapshot` are relaxed-acquire-equivalent.
