# 2026-04-25 (late evening) — v4.0.1: post-release polish

Twelve commits on top of v4.0.0, all real-world bug fixes surfaced during
the first live testing session. No new features — all are correctness
issues, train-serve drift, regressions from the v4.0.0 default-mode
change, or UX polish.

Tags:
- `v4.0.0` — sharded production release (earlier this evening)
- `v4.0.1` — this release (post-testing fixes)

## What got fixed

### Train-serve parity (61d4b80) — most important

Pre-fix, sharded `ML_BuildParameters` inline-populated a minimal
`RegimeSignals` subset but left three features at zero that the backtest
training path produced non-zero:
- `ror_slope` (trend acceleration)
- `ema_sma_spread` (EMA crossover)
- `ema_above_sma` (bullish/bearish state)

A model trained on backtest features would predict on degraded inputs at
serving time — silent train-serve drift, exactly what we wanted to avoid.

Fix: `EngineSharded_Run` now maintains a `RORRegressor` + `ema_price` on
its slow path, mirroring the legacy controller. `ML_BuildParameters`
calls `Regime_ComputeSignals` (the same function backtest's
`PortfolioController` uses) when both pointers are passed. Result: both
paths produce identical features for identical rolling-stats inputs.

### Sharded regressions from default-mode change

When sharded became the default in v4.0, several features that hooked
into the legacy `main.cpp` slow path silently broke. Each ported.

- **Settings hot-reload (93574d9)** — GUI Settings panel writes
  `engine.cfg` and sets `reload_requested`. Sharded never consumed it
  → per-core override edits never took effect until restart. Now
  re-reads cfg on the slow path; preserves boot-only fields
  (engine_mode, num_execution_cores, model paths, starting_balance).
- **GUI drag TP/SL (93574d9)** — chart's draggable TP/SL lines wrote
  to `drag_slot`/`drag_price`. Sharded ignored. Mirrors `main.cpp:585`.
- **Collect Features in foxml_suite (93574d9)** — `Backtest_Run`
  dispatcher routed any cfg with `engine_mode=sharded` to
  `BacktestSharded_Run`, which has no feature-collection plumbing.
  Carve-out: `collect_features=1` always uses the legacy path.

### Hot-swap + ML safety (a4fb389)

- **Ctrl+C in launching terminal didn't kill engine_gui** — SIGINT
  handler only set `g_engine_sharded_shutdown` but the SDL/GUI thread
  loops on `shared->quit_requested`. Added a static pointer the handler
  writes through to set both flags atomically.
- **Hot-swap to STRATEGY_ML on no-model core** silently fell back to
  SimpleDip while the GUI claimed ML. Now refused with a stderr
  explainer pointing at `core_N_model_dir`.
- **Buy Gate panel** used global `gate_direction` for all cores.
  Mixed-strategy setups (MOM = `>=`, MR = `<=`) showed wrong status.
  Added per-core `gate_direction` to PerCoreSnap; populated from
  strategy_id (MOM=1, others=0).

### Engine shutdown (528dbd2, 2829f97)

Closing the GUI window didn't kill the process quickly when WS was
mid-reconnect or REST was mid-retry. Three blocking sleeps replaced
with interruptible 100ms-poll loops:
- `BinanceStream_Reconnect` — trade WS reconnect delay
- `depth_thread_fn` — depth WS reconnect delay
- `BinanceOrderAPI` retry sleeps — REST retry + rate-limit penalties

A new file-scope inline variable `g_binance_shutdown_flag` is set by
`EngineSharded_Run` at startup so shared sleep helpers can poll it.
Net shutdown time bounded by ~100-200ms instead of 5-9 seconds.

### Sharded MOM gate direction (2829f97)

Pre-v4.0.1, the sharded hot-path `BG_Evaluate` was hardcoded to
buy-below (`FPN_LessThan`). Momentum strategy in sharded silently
traded like mean-reversion — bought dips instead of breakouts.

Fix: new `GATE_FLAG_BUY_ABOVE` flag bit. `BG_Evaluate` (both stub and
inlined-in-ExecutionCore version) branchless-selects between
`FPN_LessThan` / `FPN_GreaterThan`. `Momentum_BuildParameters` sets the
flag. Cost: ~1ns extra (both comparisons computed unconditionally;
mask picks active one). Negligible vs 40-400ns hot-path baseline.

Note: `Momentum_BuildParameters` is still a stub (TODO: full ROR + R²
port from legacy). This fix gets the DIRECTION right at the foundation;
strategy logic itself is followup work.

### Per-Core Strategy panel polish

- **ImGui ID conflict (ad9f2b9)** — column header "Apply" hashed to
  same scope as the in-row Apply button on hover, triggering ImGui's
  "2 visible items with conflicting IDs" assertion. Renamed column to
  "Swap"; added defensive PushID per Settings tab body.
- **Apply button UX (4041400)** — when chosen strategy == active, the
  button was greyed which read as "broken." Now displays a visible
  "Active" label so it's clear there's nothing to swap.
- **Settings tabs follow live core count (4041400)** — pre-fix, tabs
  read `num_execution_cores` from cfg; if missing in cfg, clamped to 1.
  Result: 4 cores running but only Core 0 tab visible. Now takes
  `live_core_count` from the TUISnapshot.
- **`cfg_write_field` bug (a1ace6d)** — silently dropped writes when
  the key didn't already exist in engine.cfg, AND used `strstr` which
  matched substrings (`mr_tp_pct=` inside `core_0_mr_tp_pct=`). Per-core
  edits made via the GUI never persisted. Fixed: append-on-not-found,
  line-anchored search.

### Buy Gate panel (ad9f2b9)

Showed only Core 0's gate. Added a per-core table (Core/Strat/Gate/
Dist/Status) at the top in sharded mode, color-coded by strategy.
Existing single-core detail kept below. Hide the redundant headline
cyan gate line on the chart in sharded (overlaps with per-core lines).

## Why v4.0.1 not v4.0.0+1 or v4.1.0

CLAUDE.md doctrine: "Patch (Z): bug fixes, guards, config changes, TUI
tweaks." Every commit since v4.0.0 fits this. No new features, no
schema changes. Bumping to 4.0.1.
