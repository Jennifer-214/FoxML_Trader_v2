Third of five v5.1 polish items. Validates the v5.0 architectural

## Bug fixed

**Notify backend test data race** (test fixture, not engine):

`NotifyCountState::events_received` was a plain `int` written by the
worker thread and read by main without synchronization. TSan flagged 2
races at `controller_test.cpp:3197` and `:3230`.

Fix: converted to `std::atomic<int>`. Backend writes the event content
first, then `fetch_add(1, release)` on the counter. Readers do
`load(acquire)` — same release-acquire ordering pattern the engine uses
everywhere.

## Accepted noise

**Test-fixture leaks** (`new R()` rigs without explicit `delete r;`):
17 sites across pre-v5.1 tests; LeakSanitizer reports ~50 MB total at
shutdown. These are **test-only**: the rigs allocate large
`OrderManagerState` + `EventLoopState` structs and let the OS reclaim
on process exit instead of cleaning up. Engine code itself doesn't
leak.

Why not fix: mass-fixing 17 scopes is busywork that doesn't catch
real defects. The leaks are bounded (per-process), reproducible,
and don't affect engine correctness. New tests since v5.0.4 already
explicit-`delete` (5 of the 7 v5.0.4 fixtures use `delete r1; delete r2`).

If a future test exercises shutdown sequences (e.g. spawning a real
slow-path thread + joining), it should clean up properly so the leak
detector can flag actual leaks among the noise.

## Known benign run-time

The engine synthetic run completed an 8-second TSan stress with zero
warnings about the engine binary itself. `g_depth_shared` reads on
slow-path are `__atomic_load_n(ACQUIRE)` and writes are
`__atomic_store_n(RELEASE)` — TSan accepts these as ordered.

The producer's per-tick fan_out updates `last_price` /
`last_volume` / `ticks_produced` via `std::atomic` — slow-path
reads with `relaxed`/`acquire` matching the writer's ordering.

`v4.7.39` `paper_reset_in_progress` atomic is also clean.
