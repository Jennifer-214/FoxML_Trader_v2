# v4.7.24 — Per-core override X-macro refactor

**Date:** 2026-04-28
**Branch:** experiment/per-core-sharding

Forward-maintenance refactor. Adding a new per-core override field used to require 4 separate edits in the same header (struct member, init zero, resolver overwrite, parser case) — easy to miss one and silently lose the override. The new X-macro pattern collapses all 4 sites into one source-of-truth list.

## Before

Adding `core_N_my_new_field` required:

1. `PerCoreOverrides<F>` struct: add `FPN<F> my_new_field;`
2. `ControllerConfig_Default<F>()`: add `cfg.core_overrides[i].my_new_field = FPN_Zero<F>();`
3. `ControllerConfig_ResolveForCore<F>()`: add `if (!FPN_IsZero(ov.my_new_field)) resolved.my_new_field = ov.my_new_field;`
4. `ControllerConfig_Load<F>()` parser block: add `if (strcmp(suffix, "my_new_field") == 0) { ... }`

Forget one and the override silently doesn't apply, with no compiler error. Pre-v4.7.24 this had ~17 fields × 4 sites = 68 lines of mechanical boilerplate. Train-serve drift risk if someone adds a field for ML and forgets to wire it through resolver.

## After

```cpp
#define PER_CORE_OVERRIDE_FIELDS(PCT, RAW) \
    PCT(take_profit_pct) \
    PCT(stop_loss_pct) \
    RAW(fee_floor_mult) \
    /* ... etc ... */

template <unsigned F> struct PerCoreOverrides {
#define _DECL_OV_FIELD(name) FPN<F> name;
    PER_CORE_OVERRIDE_FIELDS(_DECL_OV_FIELD, _DECL_OV_FIELD)
#undef _DECL_OV_FIELD
};
```

Same-name expansion drives:
- `_DECL_OV_FIELD` → struct member declaration
- `_ZERO_OV_FIELD` → init-to-zero in `ControllerConfig_Default`
- `_RESOLVE_OV_FIELD` → resolver overwrite in `ControllerConfig_ResolveForCore`
- `_PARSE_OV_PCT` / `_PARSE_OV_RAW` → cfg parser case (PCT divides /100, RAW direct)

Adding a new override field now = ONE line in the macro list. All 4 sites pick it up automatically; can't half-finish.

## Benefit for upcoming P3 migration

P3 of the settings audit (`plans/2026-04-28-settings-audit.md`) plans to migrate ~20 cfg fields (confidence_*, momentum_breakout_mult, partial_exit_*, barrier_*, etc.) into the per-core override system. Pre-v4.7.24 that was 80 manual edits. Post-v4.7.24 it's 20 list entries, mechanically safe.
