# v4.4.0 — Track E: sharded backtest unification

**Date:** 2026-04-26
**Branch:** `experiment/per-core-sharding`
**Status:** experiment branch — under testing, not released
**Plan:** `plans/track-e-sharded-backtest.md`
**Companion:** `plans/master-roadmap.md`

## Summary

Track E completes the migration from "two backtest paths
(legacy `PortfolioController` + sharded scaffolding)" to "one
backtest path (sharded, fed synthetic ticks from CSV)." After
this release, the sharded engine *is* the spec — backtest uses
the same `Regime_ComputeSignals` / `ModelFeatures_Pack` /
`EventLoop_RebuildAllParameters` call chain that the live
sharded engine uses. Adding a new ML feature, strategy, or gate
input updates ONE path, not two.

Net code: ~250 LOC deleted across the bundle (the legacy
`Backtest_Run` body is gone, ~350 LOC removed; new infrastructure
+ tests + parity harness add it back to roughly net zero
in the production code path while substantially expanding test
coverage). 544/544 controller_test passing. All four build
targets compile clean.

## Phases

Each Track E phase landed as a separate commit so individual
parts are revertable.

### E.1 — Feature collection hook (commit `0ea914f`)

The load-bearing piece. `ShardedBacktestDriver` gained an
`on_slow_path` callback. `BacktestSharded_Run` registers it when
`collect_features=1` and the callback computes `RegimeSignals`
via the same `Regime_ComputeSignals` call path the live ML
serve uses (`StrategyParameters.hpp:469`). Single source of
truth for feature production.

Driver also pushes the v4.3 expanded state (RORRegressor,
EMA price, rolling_medium, rolling_baseline, CumDelta, TickRate)
on slow-path firings, mirroring `EngineSharded_Run` lines
794-818. State pointers thread through the
`EventLoop_RebuildAllParameters` call so ML strategies see the
same fields the feature collection hook does.

`Backtest_ComputeLabelsFromSamples` extracted from the legacy
inline label block; both paths now share it.

Added 7 controller_test assertions in two groups (hook fires on
cadence, hook receives fresh state).

### E.2 — Multi-strategy support (commit `58969d9`)

Dropped the SimpleDip-only gate. Per-core strategy now reads
from `cfg.core_strategies[i]`. Per-core risk respects
`cfg.core_risk_pct[i]` override or even-split default. ML cores
load `CoreModelZoo` + init `ConfidenceScorer` with cfg
tunables — mirrors `EngineSharded_Run` lines 559-648 verbatim.

Permission grant changed from immediate-1-at-startup to
post-warmup (`rolling.count >= cfg.min_warmup_samples`). Pre-E.2
backtest fired strategies on garbage rolling stats during the
first ticks; same race `EngineSharded` already fixed in v4.0.1.

Heap lifecycle: `ml_zoos[]` static array; per-slot
`Free`-before-`Init` handles multi-run-per-process so suite
sessions running multiple Collect Features clicks don't leak
prior model handles. First-run safety verified — `Model_Free`
early-returns on null handle so `Free` on zero-init memory is
safe.

### Track E polish (commit `fb587e2`)

Closed two GAPs from the post-E.1/E.2 audit:

1. **CLAUDE.md doctrine** for Track E added under the
   Train-Serve Feature Parity invariant. Captures what's
   wired (E.1 + E.2), what's not yet wired, and the
   "adding new state during the transition" rule.

2. **E.2 regression tests** — 20 new assertions across three
   groups: CoreModelZoo Free-before-Init safety on zero-init
   memory + idempotent Free; per-core strategy + risk wiring
   via `EventLoopState_SetCoreStrategy` with mixed values +
   slot-1 risk override; warmup permission grant respects
   `STRATEGY_NONE` skip semantics.

### E.3 — Depth replay + book_imbalance gate (commit `80ace47`)

Absorbed the long-pending Phase-8a "coding c14" task. New
`DataStream/DepthReplayState.hpp` reads daily CSVs
`DepthRecorder` writes (Phase 8a format), advances a monotonic
cursor in lockstep with tick timestamps, and exposes a
`BookSnapshot<F>` that consumers read identically to
`DepthSharedState::snapshots[active]` in the live engine.

`BacktestSharded_Run` advances the replay state every tick
and pipes `imbalance` through to `EventLoop_RebuildAllParameters`
via a new optional `book_imbalance` parameter. The live path
(`EngineSharded_Run`) symmetrically reads `book_imbalance` from
`g_depth_shared` with `__ATOMIC_ACQUIRE` (pairs with the depth
thread's RELEASE on `active_idx`).

Both paths converge on a new `GATE_FLAG_BUY_BLOCKED` flag that
`BG_Evaluate` vetoes via a 1ns branchless mask. Works for
buy-above (momentum) AND buy-below strategies — unlike the
legacy `zero_gate(reason)` pattern which only zeros
`bg_price_threshold` (latent bug for momentum where
`tick.price > 0` always satisfies the gate; documented but not
fixed in this release).

When `cfg.min_book_imbalance==0` (default cfg) the gate is
inert. NULL `book_imbalance` pointer also leaves it inert
(legacy callers / tests). Strategy_BuildParameters writes
flags fresh each rebuild, so the BLOCKED bit naturally drops
when imbalance recovers.

Heap lifecycle for `DepthReplayState` follows the four-site
rule from the CLAUDE.md "Plan Review Checklist §4" — `_Init`
NULL-inits rows, `_LoadDay` frees before re-allocating, `_Free`
is idempotent + safe on never-Init'd zero memory, no
snapshot-persistence wiring (transient state).

Edge cases handled: missing depth file for a tick file's date
→ `file_present=0`, `imbalance` stays at zero → with `min>0`
the gate fails closed. `# GAP` comment lines from
`DepthRecorder` are skipped during parse.

35 new controller_test assertions across four groups: depth
replay load + advance, missing file degradation, BUY_BLOCKED
mask in BG_Evaluate, `RebuildAllParameters` book_imbalance
behavior.

### E.4 + E.5 — Walk-Forward / Sweep migration (commit `9ae6f8e`)

Doc-only. Audit found these phases are "no-op in code" — they
already inherit sharded routing through E.1's dispatcher.

`Backtest_RunWalkForward` and `Backtest_RunFullValidation`
read `BacktestResults.feature_matrix` directly (XGBoost-side
training); they never invoke the engine. The engine ran
upstream during the data-collection pass that populated
`BacktestResults`. After E.1, that upstream pass is
`BacktestSharded_Run` when `engine_mode=sharded`.

`Backtest_RunSweep` calls `Backtest_Run` per-iteration; the
dispatcher routes to `BacktestSharded_Run` based on the
overridden cfg. `use_config_override` preserves user-set
overrides.

### E.6 — Parity harness as one-shot diagnostic (commit `3dd5175`)

The plan called for E.6 as "validate legacy + sharded produce
identical features before E.7 deletes legacy." Audit found that
framing is backward — sharded is the spec, legacy is the
deprecated benchmark. Tying a regression gate to legacy parity
re-anchors the project to a path it's explicitly retiring.

Built `tests/parity_harness.cpp` + CMake target as a ONE-SHOT
diagnostic. Useful as an audit tool ("show me what legacy +
sharded did differently") and as a future cross-check if anyone
resurrects legacy. Not run as part of the test suite. Not a
release gate.

When run on `data/BTCUSDT/2024-04-26.csv backtest.cfg`, drift is
detected — but the drift is legacy-vs-sharded, not within
sharded. Sharded backtest features ↔ sharded live features
remain consistent (both default `is_buyer_maker=0` to
`RollingStats_Push`, so `volume_delta` is consistently zero in
both; both run the same `Regime_ComputeSignals` from the same
state). Train-serve parity holds where it matters.

### E.7 — Delete legacy backtest body (commit `20173fc`)

Final phase. The legacy `PortfolioController`-driven backtest
body in `BacktestEngine.hpp` (~350 LOC) is gone. `Backtest_Run`
is now a 12-line wrapper around `tt::BacktestSharded_Run` +
`Backtest_ComputeLabelsFromSamples`. Dispatcher peek logic
removed.

`BacktestSharded_Run` picked up the legacy body's two remaining
responsibilities so existing call sites keep working
transparently:

1. `CandleAccumulator` push (throttled to every 100th tick,
   same pattern as legacy + EngineSharded fan_out). Without it,
   the chart panel went empty on sharded backtest runs.
2. `TUISnapshot` populate via `TUI_CopySnapshotSharded` at
   end-of-run when `out_snapshot` is non-NULL. The dashboard
   panels (Market, Account, Stats, Positions, Buy Gate) read
   from this snapshot.

Both gated on non-NULL pointers. `last_price_d` /
`last_volume_d` tracked per-tick during the replay loop and
passed into the snapshot copy.

`cfg.engine_mode` is now PARSED-BUT-IGNORED. User cfgs setting
`engine_mode=single_core` load fine; the value just doesn't
route anywhere — every backtest goes through the sharded path.
Parser will be dropped in a follow-up release after one cycle of
grace.

What still uses `PortfolioController`: the legacy LIVE engine
in `main.cpp` (out of Track E scope), legacy strategy unit
tests in `controller_test.cpp`, and the
`BacktestStats_Compute` helper (kept; harmless).

Helper functions `BacktestData_Load`, `BacktestStats_Compute`,
etc. retained — still useful and harmless.

## What changes for users

- **Saved Runs** from before Track E: load fine. Feature pack
  is unchanged (no `MODEL_FORMAT_VERSION` bump). Same
  `MODEL_NUM_FEATURES`, same `FEAT_*` ordering.
- **Models** trained pre-Track-E: load fine. The features
  produced today match what the model trained on (sharded
  backtest features ↔ sharded live features parity holds).
- **`engine_mode=single_core` in `backtest.cfg`**: now a no-op.
  Backtest always runs through the sharded path. Live engine
  in main.cpp still respects it (deprecated separately).
- **GUI Run Backtest, Walk-Forward, Sweep**: behavior unchanged
  externally. Internally always go through the sharded path.
  Output (`BacktestResults`) shape identical.
- **Adding a new ML feature** going forward: update
  `Regime_ComputeSignals` in ONE site. Both sharded backtest
  and sharded live pick it up automatically.

## What's deferred

- Drop `engine_mode` cfg parser entirely (one release of grace
  before removing the parsing).
- Optional: factor a shared "sharded slow-path init" helper
  that both `EngineSharded_Run` and `BacktestSharded_Run` call,
  collapsing the per-feature state-add surface from two sites
  to one.
- `is_buyer_maker` plumbing into `RollingStats_Push` on both
  sharded paths (currently both default to 0, which is
  consistent for train-serve parity but degrades feature
  quality — `volume_delta` is always 0 today).
- `zero_gate(reason)` pattern fix for buy-above (momentum)
  strategies — latent pre-Track-E bug where `bg_price_threshold=0`
  always satisfies "price > 0" so the gate fires when
  `zero_gate` was supposed to veto. New `GATE_FLAG_BUY_BLOCKED`
  is the correct mechanism going forward.

## Master roadmap status

After Track E (item #1 in the roadmap), the sequence continues
with:

- **D.1 + D.2 + D.4 (Wave 1 — batched into v4.5)**: feature
  pack expansion. D.1 (book imbalance over time) was BLOCKED on
  E.3; now unblocked. D.2 (trade-flow asymmetry over time) and
  D.4 (large-trade detection) were train-serve safe pre-E and
  remain so post-E. Each adds 1-3 `FEAT_*` constants;
  `MODEL_FORMAT_VERSION` bump invalidates pre-v4.5 models.
- **D.3 (Wave 2 — spread dynamics)**: now unblocked by E.3.
  Reads from `DepthReplayState` (backtest) and
  `DepthSharedState` (live).
- **C.3 (Wave 3 — maker-only execution)**: 1-2 weeks. The big
  lift. Independent of feature work.
- Phase 1 polish, ANSI deprecation, FoxLIB catch-up, partial
  exits to sharded — all post-Wave 3.
