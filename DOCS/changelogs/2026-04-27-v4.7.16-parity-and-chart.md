# v4.7.16 — Backtest/Live Parity Drain + Chart Layout

**Date:** 2026-04-27

**Status:** experiment branch
**Prerequisite:** v4.7.0 (partials), v4.7.1 (mode-1 default)

## Summary

Two independent fixes shipped together since they were both surfaced during
the same live-readiness pass:

1. **Backtest mode-1 parity** — backtest OMS was running `event_log_mode=1`
   but the driver wasn't calling `EventLoop_DrainPostFill` after
   `OrderManager_Tick`. Result: `core_open_notional`, `core_fees`,
   `core_wins/losses`, ConfidenceScorer feedback, and SL cooldown all
   stayed at zero in backtest while live computed them correctly. Silent
   train-serve drift — backtest's ML strategy stuck armed-but-inactive,
   live's ConfidenceScorer building real signal.
2. **Chart layout** — TradingView-style sliding window. Cold start
   anchors bars to LEFT edge (bars accumulate from left), steady state
   slides RIGHT-anchored (latest bar at right edge). All horizontal
   lines and right-edge labels follow live `ImPlot::GetPlotLimits()`
   so they extend the full visible chart and snap correctly during
   pan/zoom.

## Backtest parity drain (root cause)

Live engine drainer thread runs:
```cpp
drain_with_submit();
drain_manual_closes();
OrderManager_Tick(&oms);
drain_post_fill();   // ← consumes mode-1 FillRecords
```

Backtest's `ShardedBacktest_RunTick` ran:
```cpp
EventLoop_DrainEvents(...);
OrderManager_Tick(...);
// MISSING: drain_post_fill
```

Mode-1 routes per-fill bookkeeping through `OMS::last_fill[slot]` +
`last_opened_mask`/`last_closed_mask`. `EventLoop_DrainPostFill` walks
those masks and applies the per-core stats updates. Without it, the OMS
captures every fill but the CoreContext fields never advance.

### Fix

`CoreFrameworks/ShardedBacktestDriver.hpp` — added a guarded
`EventLoop_DrainPostFill` call after `OrderManager_Tick` in both
`ShardedBacktest_RunTick` and the final-flush block of
`ShardedBacktest_Run`. Guard: `oms->event_log_mode != 0`. Mode-0 callers
keep the old behavior. Reads `cfg.sl_cooldown_cycles` from the driver's
`config` pointer.

## Chart layout (root cause)

Three iterations of feedback converged on the right design:
- Initial X view spans `vis * interval` seconds anchored differently
  per phase (cold = left, steady = right).
- All horizontal lines (price/VWAP/EMA/gates/H-L/crosshair/entry/TP/SL)
  read from `xL/xR = ImPlot::GetPlotLimits()` captured once at the top
  of the plot block — they extend the full visible chart even after
  user pan/zoom.
- Right-edge labels (price tag, GATE annotation, entry-label
  `right_edge`) anchor to live `xR`, NOT stale `cs->x_hi`.
- Per-core gate labels stagger 16px when their pixel-Y collides
  (Y-pixel collision detection over `drawn_label_py[]`).

`cs->x_lo`/`cs->x_hi` now serve only as the INITIAL view bounds passed
to `SetupAxisLimits` once. After that, `xL/xR` track the live visible
range every frame.

## Tests

with 11 assertions:

  untouched.

  matches notional, `core_fees` accumulated, mask cleared.

  even with empty tick stream.
