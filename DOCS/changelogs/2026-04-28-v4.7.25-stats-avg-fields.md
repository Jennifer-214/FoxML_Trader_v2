# v4.7.25 — Stats panel `avg W/L`, `pf`, `E[trade]` populated for sharded mode

**Date:** 2026-04-28
**Branch:** experiment/per-core-sharding

## Symptom

Stats panel showed:
```
buys: 11 (22 fills)  exits: 10 (20 fills)  W: 0 L: 10
rate: 0.0% pf: 0.00 avg W: $0.00 L: $0.00
E[trade]: $+0.00
```

`avg W`, `avg L`, `pf` (profit factor), and `E[trade]` (expectancy) all stuck at zero in sharded mode, even after dozens of trades with real P&L. Visible whenever `total_wins + total_losses > 0`. Pre-existing bug unmasked by v4.7.21's pairing fix (the W:0 L:N display made the empty avg fields more obvious — they had been zero all along).

## Root cause

`TUI_CopySnapshot` (legacy single_core path) populates `snap->avg_win`, `snap->avg_loss`, `snap->profit_factor`, `snap->expectancy` from `ctrl->gross_wins` / `ctrl->gross_losses` accumulators on the legacy `PortfolioController`.

`TUI_CopySnapshotSharded` aggregates `core_wins` / `core_losses` from per-core `CoreContext` but **never aggregates gross win/loss** — those accumulators didn't even exist on `CoreContext`. Sharded mode left all four display fields at zero.

## Fix

Add gross win/loss accumulators to `CoreContext` and wire them through:

1. **`CoreContext` gains** `core_gross_wins` and `core_gross_losses` (FPN<F>). Init to zero in `EventLoopState_Init`.
2. **`EventLoop_DrainPostFill` populates them** alongside the W/L counter increments:
   - **Partials enabled (paired path)**: when partner closes, sum the leg net P&Ls. If `total_net > 0`, add to `core_gross_wins`. Else add `|total_net|` to `core_gross_losses`. One bucket-update per trade idea, matching the per-trade W/L semantics from v4.7.21.
   - **Partials disabled (single-leg path)**: per-leg-A branch — if `was_win`, add `rec.exit_net_pnl` to gross_wins; else add `|exit_net_pnl|` to gross_losses.
3. **`TUI_CopySnapshotSharded` aggregates and computes**:
   - `gross_wins` = sum of `core_gross_wins` across cores
   - `gross_losses` = sum of `core_gross_losses` across cores
   - `snap->avg_win = gross_wins / total_wins` (when total_wins > 0)
   - `snap->avg_loss = gross_losses / total_losses` (when total_losses > 0)
   - `snap->profit_factor = gross_wins / gross_losses` (when gross_losses > 0.001)
   - `snap->expectancy = wr * avg_win - lr * avg_loss` (when total_exits > 0)

   Mirrors the legacy formulas (`EngineTUI.hpp` line ~1233) so the Stats panel renders correctly in **both** single_core and sharded modes.

## Hot path

Untouched. The new accumulators live on `CoreContext`, updated only inside `EventLoop_DrainPostFill` (slow path / drainer thread). The hot path (`ExecutionCore_Tick → BG/SG_Evaluate`) reads from `GateParameters` via seqlock and never touches CoreContext directly. p99 unchanged.
