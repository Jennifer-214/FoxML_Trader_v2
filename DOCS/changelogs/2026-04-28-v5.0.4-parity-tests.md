# v5.0.4 — Parity regression tests (2026-04-28)

Second of five v5.1 polish items. Pins the structural invariants
introduced in the v5.0 architectural switchover.

## What was added

35 new assertions across 4 test groups. Total **739/739** (was 704).

### Group 1 — OneCore wrapper identity (4 assertions)

The wrappers (`EventLoop_DrainPostFill` etc.) are LITERALLY N OneCore
calls. This test pins that invariant: future drift between wrapper and
per-core call sites would silently break per_core_slow's parity.

Two states set up identically; one runs through the wrapper, the other
runs N OneCore calls explicitly. Compares per-core counters,
notional/realized/fees, dirty flags. Repeats with non-trivial pre-state.

### Group 2 — Single-core update isolation (12 assertions)

`OneCore(core_id)` must touch ONLY `state.cores[core_id]`. Catches the
v4.7.38 latent-bug class — `EventLoop_TimeExit` indexed `state->cores[slot]`
where `slot` was a portfolio slot under partials, wrongly reading a
sibling core's state.

Sets up 4 cores with sentinel values, calls OneCore for c=2 only,
asserts c=0/1/3 unchanged across entries / exits / notional / realized.

### Group 3 — Submit queue full handling (5 assertions)

OMS submit queue capacity is 32. Pushes 33 commands, asserts at least
one rejection (capacity dependent on SPSCRing 1-slot reserve). Drains,
asserts drained count matches accepted pushes. Verifies push-after-drain
works.

### Group 4 — Topology field stability (14 assertions)

`TUI_PopulateTopology` round-trips engine_arch / producer_cpu /
drainer_cpu / nproc / slow_path_pin_offset and per-core hot/slow CPU +
poll. Re-populating with different values overwrites correctly.

## What's NOT covered

- **Threading correctness** — covered by item 3 (TSan/ASan runs).
- **Spawn + shutdown lifecycle** — requires actual thread spawning;
  out of scope for unit tests. Sanitizer runs against `engine` are
  the verification path.
- **Reset Paper park-resume** — same; threading.
