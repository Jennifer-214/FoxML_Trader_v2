# v4.7.18 — Display Honesty + Reset Cleanliness + Drag-TP/SL Restored

**Date:** 2026-04-27
**Branch:** `experiment/per-core-sharding`
**Status:** experiment branch
**Prerequisite:** v4.7.17

## Summary

Five GUI / state-cleanliness fixes from a single live observation pass:

1. **Stats panel** under partials was lying — `buys: 6  exits: 1` for one
   closed paired trade. Buys was per-fill (3 trades × 2 legs), exits
   was per-trade (`wins + losses`). Inconsistent semantics, looked like
   a counter bug. Now shows both numbers explicitly.
2. **Trade history** hid the actual core (CSV's `core_id` field is the
   portfolio SLOT under partials). Added explicit `Core` and `Leg`
   columns so each row says which core fired and which leg.
3. **Drag-TP/SL on chart** stopped working after v4.7.16 enabled real
   pan/zoom. Pre-v4.7.16 the X axis used `ImPlotCond_Always` which
   effectively suppressed pan; v4.7.16 fixed that, but ImPlot's default
   LMB→pan binding then ate the drag-TP/SL grab.
4. **Per-Core P&L panel** kept stale pre-reset history in its 1800-sample
   ring after Reset Paper, mixing old negative samples with new zeros
   and producing misleading Y-axis autofit.
5. **Reset Paper** zeroed in-memory state but left the trade-history
   CSV and OMS event log on disk — next engine restart replayed 40+
   zombie events from the prior session.

## Fixes

### Stats panel — Option C breakdown

`GUI/DashboardPanels.hpp:GUI_Panel_Stats` — under partials, displays
both numbers:

```
buys: 3 (6 fills)   exits: 1 (2 fills)
W: 0  L: 1
```

Headline = LOGICAL trades. Tail `(N fills)` = per-fill heartbeat. With
partials disabled the `(N fills)` tail is suppressed (single-leg = same
number both ways).

New field `total_exits_fills` on `TUISnapshot` (per-fill heartbeat,
populated from `state.total_exits` via `TUI_CopySnapshotSharded`).
`total_buys` was already per-fill; just relabeled in the panel.

### Trade history — Core + Leg columns

`GUI/TradeHistoryPanel.hpp:GUI_Panel_TradeHistory` — added 2 new columns
between `#` and `Entry`:

- **Core** — actual core id (`slot/2` under partials, `slot` otherwise)
- **Leg** — `A` / `B` under partials, `–` when partials disabled

Pass `partial_exit_enabled` from `TUISnapshot` to the panel render.
CSV format unchanged (`core_id` field is still portfolio slot — display
derives core + leg from it).

### Drag-TP/SL — shift-modifier routing

`GUI/ChartPanel.hpp:GUI_PriceChart` — at `BeginPlot`, dynamically swap
ImPlot's `PanMod`:

- shift NOT held → `PanMod = 0` → plain LMB drag pans (default)
- shift held    → `PanMod = ImGuiMod_Ctrl` (something the user isn't
  pressing) → pan suppressed this frame, our drag handler takes over

Drag detection also gated on `KeyShift` so plain hover near a TP/SL
line doesn't fight pan with cursor flicker.

Volume chart bindings unaffected (input map saved/restored around price
chart's `BeginPlot`/`EndPlot`).

### Per-Core P&L panel — clear ring on reset

`GUI/DashboardPanels.hpp:GUI_Panel_PerCorePnL` — saves
`last_seen_reset_seq`, compares each frame to `s->paper_reset_seq`. On
mismatch, clears the 1800-sample ring + restarts the session-seconds
axis. After Reset Paper the panel goes blank for a moment, then refills
from the new zero baseline.

### Reset Paper — rotate trade log + truncate event log

`CoreFrameworks/EngineSharded.hpp` paper-reset block:

```cpp
if (state.oms->trade_log) ShardedTradeLog_Rotate(state.oms->trade_log);
OrderEventLog_Reset(&state.oms->event_log);
g_shared.paper_reset_seq++;
```

New helpers:

- `ShardedTradeLog_Rotate(log)` — closes current file, renames to
  `logging/SYMBOL_order_history.YYYYMMDD-HHMMSS.csv`, reopens fresh
  with header. Symbol is now cached in the `ShardedTradeLog` struct at
  Init time so Rotate doesn't need it threaded back in.
- `OrderEventLog_Reset(log)` — closes the disk handle, recreates the
  file with just the header, reopens for append. Next engine restart
  replays 0 events instead of 40+.
- `paper_reset_seq` counter on `TUISharedState` + `TUISnapshot` —
  monotonic, bumped each reset. Retained-history GUI panels watch it
  to know when to clear.

## Counter "bug" root cause (no fix needed)

Investigation triggered by `buys: 6  exits: 1` led to the panel
relabel above. The actual `state.total_exits` heartbeat counter was
correct — bumping per-leg-fill exactly as designed. The display logic
was the bug.

Confirmed by tracing:
- Hot path fires `TRADE_EVENT_EXIT` per leg → drainer's
  `EventLoop_OnEvent` (mode 1 branch) bumps `state.total_exits` per call
- Each leg of a paired close = 1 OnEvent call = 1 bump
- 1 paired close = 2 bumps → `state.total_exits` += 2 (correct)
- Stats panel used `wins + losses` (per-trade) instead → showed 1
- Per-trade vs per-fill semantics weren't visible to the user
