# v5.7 — Strategy Quality: Why MOM Enters Losing Trades

**Date:** 2026-04-30
**Branch:** `feat/v5.6-display-visibility` (combined with v5.6 ship)
**Tags:** `v5.7.0` → `v5.7.6` (Phase 0/1/2/5/6 complete; 3/4 skipped)
**Tests:** 914 → 920 (+6, plus 5 SHALT_MOM_* code asserts)
**Hot path:** untouched in all v5.7 ships

## Trigger

Live paper run on 2026-04-30 showed MOM Core 0 entering at $76695 in
`regime: RANGING` — trade sat at -0.20% net for 64m, time-exit
pending, fees only. Repeated pattern: small flat trades that didn't
hit TP or SL but did eat $1.50 round-trip fees per $750 position
(0.20% drag).

Two failure modes hypothesized:
1. MOM enters in non-trending regimes (Core 0 hardcoded MOM)
2. AUTO resolves to MOM in RANGING (regime classifier bug)

## Phase 0 — Regime classifier audit (`v5.7.0`, `2ec5f83`)

**Verdict: PASS.** Replayed 18,326 existing `cat="regime"` entries
from `logging/health.jsonl` (captured during v5.4 — v5.5 paper runs).

Findings:
- TRENDING regimes sustained ~24 cycles average (not flickering)
- 197 strategy transitions across 18,326 cycles (~1 per 93 cycles)
- Distribution: 84% MR, 11% MOM, 5% EMA, <1% DIP

The 2026-04-30 symptom traces to **Core 0 hardcoded MOM**, not an
AUTO classifier bug. Core 2 (AUTO) was correctly on MR most cycles.

**Branch chosen:** Phase 2 (PASS path) — cfg + boot warning. Phases
3 (HYSTERESIS) and 4 (CLASSIFIER) skipped per audit verdict.

Detailed audit: `DOCS/changelogs/2026-04-30-regime-classifier-audit.md`.

## Phase 1 — Per-trade entry/exit logging (`v5.7.1`, `6b1f04c`)

**Foundation for measurement.** Two new health log categories
emitted by the drainer:

- `cat="entry"` on every fill open. Captures: strategy + resolved
  strategy + regime + trending_score + volatile_score + hysteresis +
  entry_price + qty + entry_notional + entry_fee + tp_pct vs floor +
  stddev_pct + long_slope + vol_delta.

- `cat="exit"` on every fill close. Captures: strategy + was_win +
  realized_return + net_pnl + entry_notional + total_fees + leg_a.

Pre-req: exposed `RegimeState.last_trending_score` /
`last_volatile_score` (the classifier wrote them as locals; v5.7.1
persists for fill-time read). Single-source rule preserved.

Post-hoc analysis tractable today:
```bash
jq 'select(.cat=="exit" and .core==N)' health.jsonl
```

## Phase 2 — Hardcoded-strategy boot guard (`v5.7.2`, `d692dec`)

PASS-branch fix. Boot-time check in `EngineSharded_Run` after
Health_LogConfigure:

- **paper run + hardcoded core** → WARN to stderr + health log
- **live run (`use_real_money=1`) + hardcoded core** AND
  `acknowledge_hardcoded_strategy_in_live=0` → ERROR + abort
- live + ack=1 → WARN logged + boot continues (operator opted in)

New cfg field `acknowledge_hardcoded_strategy_in_live` (default 0).
Documented in `engine.cfg.example` with rationale linking back to
the regime classifier audit.

## Phases 3 / 4 — Skipped

Per Phase 0 audit verdict PASS. Existing hysteresis (threshold=3)
sufficient; hardcoded `>= 2` classifier thresholds working
empirically. ~8h saved.

## Phase 5 — MOM quality filters (`v5.7.5`, `7d55c7f`)

Defensive depth. Even after Phase 2's cfg-side fix, MOM cores
(hardcoded OR AUTO-resolved) fire on ALL breakouts — quality filters
add a strategy-level "is this breakout worth taking?" check.

New cfg fields, all default 0/off (no behavior change on upgrade):

| cfg | recommended | SHALT code |
|---|---|---|
| `momentum_min_tp_margin_pct` | 0.40% | `SHALT_MOM_TP_TOO_TIGHT` (11) |
| `momentum_min_buy_delta_recent` | 0.05 | `SHALT_MOM_NO_FLOW` (12) |
| `momentum_min_r2` | 0.30 | `SHALT_MOM_LOW_R2` (13) |
| `momentum_require_last_win` | 0 (off) | `SHALT_MOM_LAST_LOST` (14, reserved) |

Filter 4 (`require_last_win`) is reserved — needs `MomentumState`
extension to track per-core last-exit win/loss flag. Wiring deferred
until v5.7.6 measurement justifies enabling.

Filters live inside the dispatcher's `STRATEGY_MOMENTUM` case branch
in `Strategy_BuildParameters`. First SHALT wins (most load-bearing
reason surfaces). All set BUY_BLOCKED + visible in v5.6 GUI Status
column as `blocked: mom:tp-tight` / `mom:low-r2` / `mom:no-flow`.

## Phase 6 — Strategy Quality dashboard panel (`v5.7.6`, `3337cc0`)

New "Strategy Quality" GUI panel. Reads `logging/health.jsonl` on
Refresh-button click (deviation from plan: simpler than 5s background
thread, no thread lifecycle).

Tail-reads last 2000 lines, parses `cat="entry"` / `cat="exit"` via
in-place key=value lookup (no JSON lib). LC_NUMERIC=C pinned around
strtod calls.

Renders:
- Per-strategy table: strat | trades | W | L | net $ | fees $ | net bps
- Per-strategy x regime entry-count breakdown

Background-thread aggregator deferred to v5.8 if measurement shows
JSONL parse cost is non-trivial.

## Recurring-bug map update

**Class 10 — Strategy-regime mismatch.** Hardcoded strategy fires in
wrong regime, AUTO mis-resolves due to hysteresis bug, or strategy
filter too loose for marginal markets. Detection: per-strategy x
per-regime quality breakdown should show no obviously-bad cells
(e.g. MOM in RANGING with negative net bps). Prevention: v5.7.2 boot
guard + v5.7.5 filters + v5.7.6 panel for ongoing observability.

## Lessons / process notes

- **Existing log data was the most valuable asset.** Phase 0 took
  0.5h instead of 2-3h because 18K+ regime entries were already
  captured. The lesson: always log enough during early ships that
  later audits can replay vs re-capture.
- **Audit-first phase pattern saves estimated effort.** Plan called
  Phase 3/4 as "if audit finds X, do Y." Audit found PASS, so 8h
  collapsed to 0h. Same pattern paid off in v5.6 Phase 5.
- **Defaults preserve behavior is harder than it looks.** Every new
  cfg field defaults to 0/off so v5.7.5 ships at no-behavior-change.
  CHANGELOG carries the recommended-after-measurement values
  separately. Operator opts in deliberately.
- **Pure-public ships kept v5.7 simple.** No private-tier strategy
  code touched; the public StrategyParameters dispatcher gained one
  case-block addition. The privacy-audit question raised mid-ship
  was answered with "all v5.7 changes are generic infrastructure."
- **Mid-ship refactor question correctly deferred.** Strategy
  plug-and-play could be tighter (X-macro), but v5.7's pace would
  have been derailed by a refactor pass. Captured as
  `STRATEGY_REFACTOR_IDEAS.md` for the next strategy-add trigger.
