# v4.6.0 — Wave 2: D.3 spread dynamics

**Date:** 2026-04-27
**Branch:** `experiment/per-core-sharding`
**Status:** experiment branch — under testing, not released
**Plan:** `plans/post-edge-hunt-c-and-d.md` (Wave 2)
**Prerequisite:** v4.5.0 (Wave 1) + v4.4.0 (Track E.3 depth replay)

## Summary

Two new microstructure features. Pattern matches Wave 1: read from
`BookSnapshot` already populated symmetrically by `DepthSharedState`
(live) and `DepthReplayState` (backtest). Push to a slow-path
`SpreadState` ring buffer in both sharded paths. Single-site
population in `Regime_ComputeSignals`.

- **`FEAT_SPREAD_BPS`** (index 32): current spread divided by mid
  price, expressed in basis points. Zero-defaults when mid_price
  is zero (cold start) or spread is zero (no depth feed).
- **`FEAT_SPREAD_ZSCORE`** (index 33): z-score of current spread
  vs trailing 1024-sample window. Captures "spread is unusually
  wide right now" — a regime/liquidity signal that's hard to read
  from the absolute spread.

## Changes

- `ML_Headers/FlowFeatures.hpp` — new `SpreadState<F, W>` struct
  identical in shape to `LargeTradeState<F, W>` (ring + running
  `sum + sum_sq` for O(1) mean+variance, z-score). Kept as a
  separate struct for clarity at call sites and future divergence
  (e.g. spread-specific normalizations).

- `ML_Headers/ModelInference.hpp` — 2 new `FEAT_*` constants
  (32, 33). `MODEL_NUM_FEATURES` 32→34. **`MODEL_FORMAT_VERSION`
  v3→v4 — old v3 models fail load.** `FEATURE_LOOKBACKS[]`
  extended.

- `Strategies/RegimeDetector.hpp` — `RegimeSignals<F>` gains
  `spread_bps` + `spread_zscore` (both `double`). `Regime_-
  ComputeSignals` gains 3 new optional params at the tail:
  `spread_state` (void*), `current_spread` (double),
  `current_mid_price` (double). Population: `spread_bps =
  current_spread / current_mid_price × 10000` when both non-zero,
  else 0; `spread_zscore = SpreadState_ZScore` when state non-null,
  else 0.

- `Strategies/StrategyParameters.hpp` — `MLBuildContext` gains
  `spread_state` + `current_spread` + `current_mid_price`.
  `ML_BuildParameters` forwards them into `Regime_ComputeSignals`.

- `CoreFrameworks/ControllerEventLoop.hpp` —
  `EventLoop_RebuildAllParameters` gains the 3 new params; wired
  into `MLBuildContext` AND the `STRATEGY_AUTO` regime path.

- `CoreFrameworks/ShardedBacktestDriver.hpp` — driver gains
  `spread_state` (mutable) + `current_spread` / `current_mid_price`
  pointer holders. Slow-path block pushes
  `SpreadState_Push(*current_spread)` after the existing
  Wave 1 pushes. RebuildAllParameters call passes the new params
  (current_spread / current_mid_price dereferenced when non-null).

- `Backtest/BacktestSharded.hpp` — new static-locals: `spread_state`,
  `spread_holder`, `mid_price_holder`. Reset each backtest run.
  Per-tick: refresh `spread_holder` + `mid_price_holder` from
  `depth_replay.current.spread` / `mid_price` alongside the
  existing `book_imbalance_holder` update. Driver wiring sets
  `drv.spread_state = &spread_state`,
  `drv.current_spread = &spread_holder`,
  `drv.current_mid_price = &mid_price_holder` (when
  `cfg.depth_enabled`). `on_slow_path` hook passes the new state
  pointers + current values to `Regime_ComputeSignals` so feature
  collection matches what the ML strategy sees at serve time.

- `CoreFrameworks/EngineSharded.hpp` — new static-local
  `spread_state`. `fan_out` lambda captures by reference. Slow-path
  block reads `g_depth_shared.snapshots[active].spread` /
  `mid_price` alongside the existing `imbalance` read; pushes
  `SpreadState_Push(book_spread)` when `cfg.depth_enabled`.
  `EventLoop_RebuildAllParameters` call passes the new params.

- `tests/controller_test.cpp` — 10 new assertions across two
  groups: SpreadState init / uniform-window-zero / spread-window-
  zscore / Last / ring eviction; spread_bps formula in
  `Regime_ComputeSignals` (including cold-start mid==0 zero-default).
  586/586 passing (was 576).

## Cadence — train-serve parity check

`SpreadState` pushes at slow-path cadence in both sharded paths
with identical inputs (`BookSnapshot.spread`). `current_spread` +
`current_mid_price` are read on the same slow-path with identical
sources. Same shape as v4.5 D.1 — train-serve drift cannot enter.

When `cfg.depth_enabled=0`, both paths skip the SpreadState push
AND pass `current_spread=0` / `current_mid_price=0` to
RebuildAllParameters → `spread_bps=0` and `spread_zscore=0`
across the board. Documented inert behavior, consistent both
paths.

## What changes for users

- **`MODEL_FORMAT_VERSION` v3 → v4.** All v3 models (including
  any retrained at v4.5 from Wave 1) fail load with version-
  mismatch error. Retrain at v4.6 to use D.3 features.
- **`MODEL_NUM_FEATURES` 32 → 34.** `MODEL_MAX_FEATURES` (64)
  unchanged from v4.5.
- **No new cfg fields.** Window size hardcoded at 1024 like
  Wave 1 states.
