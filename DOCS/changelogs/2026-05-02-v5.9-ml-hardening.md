## Trigger

The v5.8 paper-test soak surfaced a class of silent-failure modes
that the existing test suite + readiness checks didn't catch:

1. **Silent ML model load failure** — operator paper-tested for
   hours without realizing the ML core fell through to SimpleDip
   because the model file was missing/refused. No GUI surface, no
   stderr CRITICAL.
2. **Silent NaN propagation** — feature-pack and label-compute paths
   could produce NaN/Inf without any guard, polluting training
   matrices and producing junk predictions at inference.
3. **Silent cfg defaults** — backtest.cfg with missing per-core
   strategy fields fell through to SIMPLE_DIP across the board with
   no boot warning.
4. **Silent ConfidenceScorer fallback** — invalid tau values
   silently overrode to defaults at init time, no log.
5. **Silent walk-forward purge violation** — folds could violate the
   purge gap invariant without any post-gen check.

The audit (`DOCS/V5_9_ML_HARDENING_AUDIT.md`) catalogued 27 findings
across 10 categories. The plan is to close them in 6 phases:

- **Phase 0** — audit doc + ML invariants spec (~3h)
- **Phase 1** — visibility + immediate guards (~11h, 9 findings)
- **Phase 2** — edge cases + observability polish (~5h, 5 findings)
- **Phase 3** — train-serve parity regression test (~5h)
- **Phase 4** — feature standardization (~7h, MODEL_FORMAT_VERSION 5→6)
- **Phase 5** — recipes + readiness extensions (~4h)
- **Phase 6** — postmortem (~2h)

This file documents Phases 1 + 2 (shipped). Phases 3–6 will append
as they ship.

### v5.9.0 — NaN/Inf guards + WF purge post-check + stamp_format_version

Closes V5_9_AUDIT-#1, #6, #8, #15.

- **Feature pack output validation.** `Features_PackAll` now
  returns `-1` sentinel when any feature's FPN value is outside the
  finite envelope (via new `FPN_IsValidFinite` branchless helper at
  `FixedPoint/FixedPointN.hpp:721`) OR when the float-cast produces
  NaN/Inf. Caller branches on the sentinel and skips the prediction
  cycle. Two-layer check catches both FPN saturation (1e15
  threshold) AND IEEE-754 NaN.
- **Prediction NaN/Inf guard.** `Model_Predict` and
  `Model_PredictMulti` callers in `StrategyParameters.hpp` check
  `isnan(prediction) || isinf(prediction)` post-call; skip the
  cycle on hit. Previously, NaN flowed straight into the threshold
  comparison and the entry gate fired on essentially-random
  outcomes.
- **Walk-forward purge post-check.** `ValidationSplit_Generate`
  now loops folds after generation and FATALs on any fold where
  `train_end + purge_gap > test_start`. Catches the
  PurgeGap_Compute → fold_size_n math drift class.
- **Stamp format version.** New `stamp_format_version=1` field
  emitted into stamp body when `format_version >= 5`. Both bash
  (`tools/stamp_model.sh`) and in-process emitters parity-pinned.
  Defensive: gives v5.9.3 (when MODEL_FORMAT_VERSION moves to 6) a
  forward-compat schema field to bump.

### v5.9.0d — Train Model worker thread (UI freeze fix)

Closes V5_9_AUDIT-#7.

`Train Model` button on the foxml_suite Training panel previously
ran XGBoost synchronously on the UI thread, freezing for 5–30s
during training. Lifted into a worker thread mirroring the
v5.8.7 fullvalidation_worker_fn pattern:

- `train_model_worker_fn` — snapshots user-modifiable state
  (max_depth, learning_rate, n_estimators, label_type,
  model_path) at entry; polls `state->tm_cancel` between
  `XGBoosterUpdateOneIter` calls (bounded latency = one iter
  time, ~100ms–1s); sets `tm_complete=1`, `tm_running=0` on
  every exit path (success, error, cancel).
- UI shows pulsing `ProgressBar` + `Cancel Training` button
  while the worker is alive.
- `pthread_detach` (no join, mirrors FV worker pattern).

### v5.9.1 — edge-case + observability polish

- **Label NaN guards per-type.** `BacktestStats.nan_labels_total +
  nan_labels_dropped` counters. Wrapper at
  `BacktestEngine.hpp:510` (the per-sample `label_fn` loop):
  binary→`0.5f`, regression→`0.0f`, multiclass→`NAN` sentinel.
  Both training paths (walk-forward + held-out TrainSingleFold)
  filter NAN-marked samples at compaction. Past Runs panel
  surfaces `nan_labels_total` when > 0 with red tooltip.
  In practice, only triggers on degenerate input (sample_price=0)
  — not reachable on real Binance ticks. Defensive upgrade only.
- **Warmup progress observable.**
  `PerCoreSnap.warmup_progress_pct` (uint8_t, 0..100) populated
  from `cores[i].slow_state->rolling_short.count` vs
  `min_warmup_samples` (engine default 64 fallback).
  `EventLoop_RebuildOneCore` emits `[core N] warmup complete
  (...)` to stderr exactly once per core per session via the new
  `CoreContext.warmup_log_emitted` edge flag. ML Status panel
  shows `warmup: NN%` line when pre-warmup with tooltip
  explaining why predictions aren't firing yet.
- **ConfidenceScorer tau<=0 hardening.**
  `ConfidenceScorer_Init` logs WARN when tau<=0; previously
  silent fallback to default. ControllerConfig parser explicitly
  rejects tau<=0 — the error is caught at the cfg layer instead
  of silently overriding at init time.
- **Confidence hard-floor (DEFAULT DISABLED).** New cfg
  `confidence_hard_block_threshold` (default `0.0` = disabled,
  preserves pre-v5.9.1 behavior bytewise; audit-recommended
  `0.05` once retrained). When `> 0.0` AND
  `confidence_enabled=1`, hard-blocks ML entries with raw
  confidence below the floor; emits `SHALT_LOW_CONFIDENCE` on
  the strategy_halt_reason channel. New
  `MLBuildContext.out_strategy_halt_reason` pointer wires
  through to the dispatcher's existing
  `strategy_halt_reason` parameter — single-source-of-truth
  for SHALT propagation.
- **`DOCS/ML_TRAINING.md` (NEW).** Class-weight tuning guidance
  for the trainer side. Calls out the v5.8 paper-test
  4.2/48.3/47.5 PEAK_VALLEY_STABLE distribution and recommends
  inverse-frequency `sample_weight`. Anti-patterns: SMOTE
  up-sampling (look-ahead bias), threshold-lowering
  (compounds noise), half-strength weights (heuristic).

### v5.9.1a — init polish (uninit-field fix)

Caught by v5.9.1 parity audit (`/ml-audit parity`):
`EventLoopState_Init` doesn't explicitly initialize the 7 new
CoreContext fields added in v5.9.0b + v5.9.1:

- `model_load_failed` (v5.9.0b)
- `last_ml_critical_log_us` (v5.9.0b)
- `last_ml_threshold` (v5.9.0b)
- `last_ml_effective_threshold` (v5.9.0b)
- `nan_feature_events_total` (v5.9.0b)
- `nan_prediction_events_total` (v5.9.0b)
- `warmup_log_emitted` (v5.9.1)

Stack-allocated `EventLoopState<F>` doesn't zero memory — these
fields read garbage on the first slow-path rebuild. In practice
the layout placed them next to other zero-init'd fields so most
boots happened to read 0, but it's not a guarantee — the
warmup-complete log could have fired spuriously, the NaN
counter could have read non-zero on first display, etc.

Single-commit fix: explicit init for all 7 fields at the end
of the existing per-core init loop, with comment pointing to
the v5.9 audit.

### v5.9.4a — Full closure: paper-test bugs + 4 carryovers + v5.10 design notes

Caught in 2026-05-02 paper testing soon after v5.9.4 ship:

**Paper-test bug B (auto-stamp gate).** Auto-stamp on held-out was
silently no-op'ing because the gate was a single boolean that
conflated three distinct error states. Fix: 3-state diagnostic
(skipped / refused-for-cause / completed) at suite UI.

**Paper-test bug C (multiclass "no edge" diagnosis).** Display
hardcoded `val_acc < 0.52f` as the "no edge" threshold — fine for
binary, wrong for multiclass. A 3-class with 5.9/47.4/46.7
distribution showed val=46.7% which "looked like 50% random" but
the actual baseline was max-class-freq=47.4%. Fix:
`multiclass_baseline_accuracy()` helper in `BacktestEngine.hpp`
returns `max(1/K, max_class_freq)`; diagnosis bands relative to
baseline (≤baseline+1pp = no edge / [+1pp,+3pp] = marginal /
≥+3pp = real edge).

**4 deferred items closed:**

1. **Warmup log strategy name** (V5_9_AUDIT carryover).
   `[core N] warmup complete` line now includes the active strategy
   name (e.g. `[core 0] warmup complete (64/64 samples) — ml_strategy

2. **`model_num_outputs` stamp body field.** Catches output-dimension

3. **`training_poll_interval` cadence WARN.** Engine boot WARN when

4. **Gap I worker auto-unlink orphan scaler.** Train Model worker

## Lessons learned

### 1. Surface G stamp body extension > format-version bumps

Phase 4 was originally planned as `MODEL_FORMAT_VERSION` 5→6 to add
the scaler. Mid-sprint we recognized: scaler is a sidecar file, not
a model file change. Stamp body's `has_scaler_*` forward-compat
flags handle it without breaking old stamps. Generalized: any new
parity-enforced field should be added via `has_<field>` flag, not
format bump. **Format bumps lose data; flag extensions don't.**

KDD #15 candidate (parity-tested-by-construction).

### 2. Display ↔ execution invariant rigor at multiclass boundaries

Bug C (hardcoded 0.52) was caught only because a paper test
happened to have a 3-class label that looked numerically similar
to a noisy binary. The display branch had been added before the
multiclass label landed — display path didn't know about K. Same
class of bug as v5.6.0's "every BG/SG term must have a GUI surface"
invariant; multiclass is the next dimension that needs the same
discipline.

Fix is single-source-of-truth helper (`multiclass_baseline_accuracy()`)
that consumes the actual class counts. Anywhere display code
references the baseline, route through the helper.

### 3. Silent-failure-class items aren't deferrable
