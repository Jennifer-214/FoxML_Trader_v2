# v4.7.23 — Strategy-aware settings tab filtering

**Date:** 2026-04-28
**Branch:** experiment/per-core-sharding

P2 of the settings audit. The panel now hides settings sections that aren't relevant to the strategies actually configured on the cores.

## Per-core tab

Each per-core tab now only shows the "Strategy-Specific" override fields that match the core's resolved strategy. If Core 1 = EMA Cross, Core 1's tab shows only:
- EMA TP %
- EMA SL %

Hidden: DIP TP/SL, MR TP/SL, MOM TP σ / SL σ, ML TP/SL, ML Threshold.

If Core 2 = AUTO, all strategy-specific fields show (since AUTO routes to any of the 4 strategies at runtime).

If Core 0 = STRATEGY_NONE, the Strategy-Specific section is hidden entirely.

The strategy resolution prefers live snapshot data when available; otherwise falls back to the per-core dropdown choice in the panel state.

## Global tab

Strategy-tuning sections in the Global tab (`SimpleDip Tuning`, `MeanReversion Tuning`, `Momentum Tuning`, `EMA Cross Tuning`) hide when no configured core uses that strategy.

ML-related sections (`FoxML`, `Validation`, `Models`, `Barrier`) hide when no core is configured for `STRATEGY_ML`. The user gets the noise out of the panel until they actually configure an ML core; at that point the relevant knobs appear.

`STRATEGY_AUTO` triggers all strategy sections to show (since AUTO can dispatch to any).

The strategy-agnostic sections — `Trading`, `Entry Filters`, `Risk Management`, `Kill Switch`, `Regime Detection`, `EMA Gate`, `Danger Gradient`, `Session Filters`, `Engine Timing`, `Per-Core`, `Tick Recording`, `Operational Monitoring`, `Toggles` — always show.

## Implementation notes

- Two new helpers in `SettingsPanel.hpp`:
  - `per_core_field_strategy(key_suffix)` — maps `simpledip_*`, `mr_*`, `momentum_*`, `emacross_*`, `ml_*` prefixes to STRATEGY_* constants. Anything else returns -1 (agnostic).
  - `global_section_strategy(section)` — maps section name to STRATEGY_* constant.
  - `any_core_uses_strategy(s, strat)` — scans `s->per_core_strategy[]` for the strategy or AUTO.
- Per-core tab: pre-scans each section for any visible field before rendering the header — avoids empty-header artifacts when a section's fields are all filtered out.
- Source of truth for "is this strategy configured" is `SettingsState::per_core_strategy[]` — the user's intent. If they pre-configure a core for ML in the dropdown, the FoxML section appears immediately, even before they hit Apply.

No cfg semantic changes. No test coverage changes (panel rendering is GUI-only). 689/689 tests pass.
