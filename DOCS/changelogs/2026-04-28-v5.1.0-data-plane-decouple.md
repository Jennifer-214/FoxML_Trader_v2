# v5.1.0 — Per-core data-plane decoupling (2026-04-28)

Fourth of five v5.1 polish items. Closes the redefined-as-audit
Phase A from the v5.0 master plan. **Each engine now OWNS its
rolling/regime/flow state in per_core_slow** rather than reading
producer-owned shared state.

## Architectural change

### Before (v5.0.x)

```
Producer thread:
  - fan_out (per tick): write SHARED rolling stats, ema, regime_ror,
                         cumdelta, tick_rate, flow, large_trade, ...
                         every poll_interval ticks
  - main slow-path body: write SHARED book_imb_history, spread_state

Per-core slow-path threads (per_core_slow):
  - Read SHARED state on cadence (cross-thread reads, eventually
    consistent on x86)
  - Run RebuildOneCore with shared pointers
```

### After (v5.1.0, per_core_slow)

```
Producer thread:
  - fan_out (per tick): write per-core ema_price for ALL N engines
                         (single-writer per copy)
  - shared-state pushes SKIPPED — dead in per_core_slow

Per-core slow-path c (single-writer of own slow_state):
  - Cadence: read current price/volume from atomics
  - Push to OWN slow_state.rolling_short / .rolling_long / .regime_ror
                       / .cumdelta / .tick_rate / .flow / .large_trade
                       / .book_imb_history / .spread_state
  - Run RebuildOneCore with PER-CORE pointers (no cross-thread reads)
```

### Centralized arch (unchanged)

Producer's slow-path body still writes SHARED state and the per-core
wrappers read shared. Functionally equivalent to v5.0.x. Asymmetric
with per_core_slow but kept for backwards-compat / benchmark / legacy
comparison. Symmetric refactor deferred to v5.2.x.

## What's new

### `CoreSlowState<F>` struct

Holds 12 fields per engine:
- 4 `RollingStats<F, W>` with W ∈ {128, 256, 512, 1024}
- `RORRegressor<F>`, `FPN<F> ema_price`
- `CumDeltaState<F>`, `TickRateState`
- `BookImbalanceHistory<F, 1024>`, `FlowState`, `LargeTradeState<F, 1024>`,
  `SpreadState<F, 1024>`

Located in `CoreFrameworks/ControllerEventLoop.hpp` as a sibling of
`CoreContext<F>`.

### Heap allocation

`CoreSlowState<F>` is ~3MB per engine due to template-fixed window
arrays. 16 inline copies on `EventLoopState::cores[16]` would overflow
the 8MB default stack on tests that put `EventLoopState` on the stack.

`CoreContext::slow_state` is therefore a pointer; allocated in
`EventLoopState_Init`, freed in new `EventLoopState_Free`. Slow-path-
only access — the indirection cost is negligible at slow-path cadence.

### Per-tick replication for ema_price

Producer's `fan_out` updates `ema_price` for each engine's `slow_state`:

```cpp
if (cfg.engine_arch == ENGINE_ARCH_PER_CORE_SLOW) {
    for (int c = 0; c < num_cores; ++c) {
        if (state.cores[c].slow_state) {
            state.cores[c].slow_state->ema_price = ema_price;
        }
    }
}
```

Cost: N × FPN<F> word writes per tick. Trivial (~1 word, naturally
aligned, fits in cache).

### Per-cadence pushes in slow-path lambda

Each per-core slow-path thread, before calling `RebuildOneCore`, pushes
the latest price/volume to its own `slow_state`. Mirrors what the
producer's fan_out does for shared state in centralized arch — same
input, same cadence, same pushes. Single-writer per copy (the thread
itself).

### Skip shared writes in per_core_slow

`EngineSharded.hpp:881` and `:1105` gates skip the producer's shared-
state pushes when `engine_arch == ENGINE_ARCH_PER_CORE_SLOW`. The
shared state stays initialized but never written/read in that arch.

### `EventLoopState_Free`

Idempotent helper that frees all `slow_state` pointers and NULLs them.
Safe to call twice. Engine teardown should call this; tests already
LeakSanitizer-clean for the new fields (still get noise from older
tests' `new R()` rigs, documented as accepted in v5.0.5).

## Invariant B added (CLAUDE.md)

> **Per-Core Data-Plane Single-Writer**: Each `CoreContext::slow_state`
> is owned by exactly one writer:
> - Per-tick `ema_price`: producer thread (writes ALL N engines' copies
>   in fan_out), engines read with relaxed acquire — eventual consistency
>   acceptable on x86 (same as pre-v5.1 shared design but per-engine
>   targets eliminate cross-engine read races)
> - Per-cadence fields (rolling/regime/flow/depth-history): producer
>   thread (centralized — single writer to N engines) OR per-core slow-
>   path thread c (per_core_slow — writes only c's slow_state). Same-
>   thread read in both arches.

## Tests

739/739 pass. Existing OneCore identity + isolation tests (v5.0.4)
continue to verify per-core mutation correctness. The data-plane shape
change is backward-compatible at the read API (Regime_ComputeSignals
takes the same set of pointers).

## Backwards compat

- Snapshot persistence: **unaffected** (snapshot persists no `slow_state`
  fields — verified during v5.0.2 readiness check).
- Cfg: no new fields.
- Centralized arch: unchanged behavior.
- Backtest path: still uses shared state (deferred to v5.2.x for symmetric
  decoupling — currently functions correctly).

## What's deferred (v5.2.x)

1. **Symmetric centralized**: have centralized arch also use per-core
   `slow_state`, dropping the shared `static` declarations entirely.
2. **Backtest path**: same — drop the static-storage shared state in
   `BacktestSharded.hpp`.
3. **Per-core window size override**: now possible since each engine has
   its own copy. Requires runtime-sized buffers (current window is a
   template parameter).

## Rollback

Tag `pre-data-plane-decouple` at v5.0.5 head. Revert is mechanical
(pointer field + populate sites). The shared state declarations are
still in place and would resume use.
