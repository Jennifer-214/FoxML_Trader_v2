| 4.7.3 | 2026-04-27 | **Zombie position fix + CSV flush + partials bitmap mapping** *(experiment branch)* — Three bugs found from 4-hour live engine_gui soak. **(1) Zombie positions: ROOT CAUSE FOUND**. `ExecutionCore_Tick` was discarding `SPSCRing_TryPush` return values — if the event ring filled (drainer briefly stalled), the exit/entry event was silently dropped BUT the active flag was still cleared by the unconditional mask update. Result: `Portfolio.active_bitmap` shows the position but `core->active=0`, so hot path's `can_exit = active & sg_fires` evaluates to 0 forever. AND with active=0, the gate falls back to `cached_params.sg_stop_loss_price` (slow-path-computed against current bg threshold, not the entry's SL) — which on a sustained price move tracks current price closely → SL never fires regardless of how far price moves. Position stays open until day-boundary force-close. Fix: track each leg's push success, mask out failed pushes from the active flag toggle, log to stderr on push failure. Failed pushes now leave active unchanged so the next tick retries naturally (sg_fires_a still TRUE if SL still in range). **(2) Trade log buffering**: `ShardedTradeLog` opened in default fully-buffered mode; trade rows sat in 8KB libc buffer until clean shutdown, so mid-session GUI/cat reads showed only the prior session's flushed data. Switched to line-buffered (`setvbuf(_IOLBF)`) so each `\n`-terminated row auto-flushes. **(3) Bitmap mapping under partials**: `ControllerEventLoop.hpp` slot-active checks (`active_bitmap & (1u << slot)`) treated `slot` as both the CoreContext index AND the portfolio slot; under partials, core c's actual portfolio slots are 2c and 2c+1, so checking bit `c` looked at the wrong bitmap position. Added `Sharded_CoreSlotMask(core_id, partials)` helper, applied to ratchet_sl clear, regime-change ratchet, and Phase 3 MTM unrealized walk. The MTM site now sums unrealized P&L across both leg slots when paired. Hot-path latency unchanged (changes are in the rare-branch + slow path). 659/659 tests. Existing zombie positions auto-recover on restart via the v4.7.1 snapshot loader's bitmap walk. |
